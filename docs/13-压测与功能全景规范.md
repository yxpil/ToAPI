# ToAPI — 压测与主流功能全景规范

> 两部分：① 内置压测引擎（对标 JMeter 的常用 80%，不做分布式集群）；
> ② 主流 API 工具功能全景对照，明确 ToAPI 的覆盖线与取舍。

## 1. 压测能力

### 1.1 压测模型 `load_profile`（存 api/collection 上或独立配置）
```jsonc
{
  "target": {"type": "api", "id": "..."},
  "vus": 50,                 // 并发虚拟用户
  "rampUpSec": 30,           // 线性加压
  "durationSec": 300,        // 或 iterations: 100000
  "rpsCap": 200,             // 全局限速（可空）
  "thinkTimeMs": [100, 500], // 每 VU 请求间隔随机区间
  "dataFeed": {"path": "users.csv", "strategy": "sequential"},  // 每迭代取一行注入运行时变量
  "thresholds": [            // 通过线，跑完判定 PASS/FAIL
    {"metric": "p95", "op": "<", "value": 800},
    {"metric": "errorRate", "op": "<", "value": 0.01}
  ]
}
```

### 1.2 引擎
- 主进程 worker 池（每 VU 一个轻量协程式循环，共享 keep-alive 连接池），**仍走 HttpEngine**：伪装/代理/CookieJar 与单发一致。
- 变体规则：每 VU 独立运行时变量；dataFeed 行注入 `{{row.*}}`；脚本照常执行（压测中脚本熔断阈值收紧为 1s，防脚本拖垮引擎）。
- 实时聚合：1s 桶聚合（count、min/max/p50/p90/p95/p99、错误数、RPS），事件推渲染进程画实时曲线。

### 1.3 存储（追加进 03 号文档）
- `load_run(id, profile_json, started_at, finished_at, vus, total, error_count, p50, p90, p95, p99, rps_avg, verdict, report_path)`
- `load_run_bucket(id, run_id REFERENCES load_run ON DELETE CASCADE, bucket_ts, count, errors, p50, p95, p99, rps)`
- **不存逐请求明细**（压测量级下 DB 会爆）；抽样保留每错误类型前 20 条响应快照进 history（标记 `isLoadSample`）。

### 1.4 报告
- HTML 报告：曲线（RPS/延迟分位/错误率）、阈值判定、环境信息、dataFeed 摘要；可导出。
- 两次 run 对比视图：分位数差值表 + 回归标记。

### 1.5 安全闸门（压测是双刃剑，默认收紧）
- 目标 host 不在当前环境 host 清单 → 强制确认弹窗，文案明示「确认你有权对该目标发起压测」。
- 非 localhost/内网目标：默认 `vus ≤ 20、rpsCap ≤ 50`，超限需勾选"我确认有授权"并记录进审计日志。
- 一键熔断：UI 常驻停止按钮；错误率 >50% 持续 10s 自动暂停并询问。

### 覆盖线声明

- **已覆盖**：调试、环境/集合/全局/运行时变量、脚本、断言、Runner、链式、定时、压测（单机）、文档协作、CI 集成、AI 调用、**跨部门文件互传（`.tapi` 导出/导入 + CLI 直跑）**。
- **Postman 本地全量兼容（M9 四批）**：资产互操作、`pm.*`、动态变量、数据驱动 CLI、五种协议、本地 Mock、OpenAPI、保存示例、认证长尾；范围边界见 23 号文档 §9。
- **同类工具互操作**：Apifox 资产经 Postman v2.1 / OpenAPI 桥流入流出（B4，23 号文档 §7.1）；不做 Apifox 云协作。
- **刻意不做**：云账号/工作区/云 Mock/云 Monitor、Postman Flows / AI Agent、分布式压测、插件市场、抓包录制。
- 每个版本发布时本表随功能状态更新，作为对外能力声明的唯一事实源。

## 3. IPC / 测试（IPC 清单并入 04 号文档 §3.5；用例纳入 07 号文档执行清单 §2.10）

- IPC：`load:run / load:cancel / load:get / load:compare / event:load-tick`（1s 桶推送）。
- 测试（07 号文档 §2.10）：
  - 对本地靶场压测：RPS 达成率 ±5%、分位数与靶场实测一致、阈值判定正确
  - dataFeed：行耗尽策略（stop/cycle）正确；`{{row.*}}` 注入可见
  - 闸门：外网目标默认限额生效；审计有记录；自动暂停触发
  - 引擎自身：300s × 200 RPS 下主进程 CPU <50%、内存增长 <100MB（防泄漏回归）
