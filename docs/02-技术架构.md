# ToAPI — 技术架构

## 1. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 壳 | Electron（最新稳定版） | 跨平台桌面壳，Node 能力直达网络层，可绕过浏览器 CORS |
| 视图 | React 18 + TypeScript + Vite | 生态成熟，HMR 快 |
| 样式 | 原生 CSS 变量 + 少量工具类 | 不引 UI 框架，保证"画布 + 浮层 + 药丸"视觉完全可控、包体积小 |
| 数据库 | Node 内置 `node:sqlite`（DatabaseSync） | 同步 API、零原生依赖、免按 Electron ABI 重编译；Electron 45 内置 Node 24.22 实测可用（2026-10-24）。原选 better-sqlite3 因原生编译风险替换，接口形态一致 |
| HTTP 引擎 | 主进程 Node `undici` | 完整控制 Header 顺序、代理、重定向、超时；渲染进程永不直接发请求 |
| 脚本引擎 | worker_threads + node:vm 双层隔离 | 原选 `isolated-vm` 只有 abi137/147 预编译，Electron 45 是 abi150 且源码编译需 VS 工具链；改为"独立 worker 内的 vm 上下文"，同样切断 require/process/fetch，且 `worker.terminate()` 可强杀异步阶段的失控脚本（Node 与 Electron 行为一致，零原生依赖） |
| 状态 | Zustand（渲染进程内） + IPC 同步 | 轻量，无样板 |
| 构建 | Vite（渲染层）+ esbuild（主进程/preload 打包为 CJS） | 沙箱化 preload 需 CJS；esbuild 启动快，dev 走 vite HMR + esbuild watch |

## 2. 进程架构

```
┌─────────────────────────────────────────────────┐
│  Renderer (React)                               │
│  请求编辑器 / 响应查看器 / 树 / Runner 面板        │
│        │  invoke('api:send', payload)           │
│        ▼                                        │
│  Preload (contextBridge)                        │
│  只暴露白名单 API：window.toapi.invoke(channel)  │
│        │                                        │
│  Main Process                                   │
│  ├─ HttpEngine   发请求（undici + 代理 + CookieJar）│
│  ├─ ScriptVM     isolated-vm 执行用户 JS 脚本     │
│  ├─ PyBridge     Python 案例子进程（stdio JSON-RPC）│
│  ├─ Codegen      api↔代码双向转换（cURL/JS/Python）│
│  ├─ MdEngine     MD 解读（端点识别）+ .tapi.md 解析/运行/同步│
│  ├─ TapiCodec    .tapi 导出/导入/校验/合并        │
│  ├─ OpenAPI      Local HTTP API（127.0.0.1 + token）│
│  ├─ McpServer    MCP stdio / Streamable HTTP      │
│  ├─ Scheduler    定时任务（cron/interval/once + 系统唤醒）│
│  ├─ MacroPlayer  动作宏录制/回放（白名单控件）      │
│  ├─ LoadGen      单机压测引擎（VU 池 + 1s 桶聚合） │
│  ├─ Notifier     通知路由（Toast/通知中心/OS/Webhook）│
│  ├─ AiClient     OpenAI 兼容客户端（脱敏/草稿/审计） │
│  ├─ VarResolver  {{var}} 插值与提取器             │
│  ├─ Repo         better-sqlite3 数据访问层        │
│  └─ IpcRouter    所有 channel 的入口与校验        │
└─────────────────────────────────────────────────┘
```

### 硬性规则
- **渲染进程零 Node 权限**：`nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`。
- **所有网络流量只走主进程**：避免 CORS、便于统一伪装/代理/日志。
- **所有 SQL 只走 Repo 层**：禁止在 IPC handler 里写裸 SQL。
- **用户脚本永不直接接触主进程对象**：通过桥接函数（reference + apply）通信。

## 4. 关键数据流：一次带脚本的请求

```
点击发送
  → 渲染进程组装 RequestDraft，IPC 到主进程
  → VarResolver 解析 {{var}}（环境 + 全局 + 运行时变量）
  → ScriptVM 执行 Pre-request 脚本（可修改 draft、可 toapi.request 发子请求）
  → HttpEngine 发送（应用伪装：UA/Headers/代理/CookieJar）
  → 收到响应 → ScriptVM 执行 Post-response + Test 脚本
  → 提取器写回运行时变量（供链式下一跳使用）
  → 结果（请求快照 + 响应 + 脚本日志 + 断言）入库 + 推回渲染进程
```

## 5. 性能预算

| 指标 | 目标 |
|---|---|
| 冷启动到可交互 | < 1.5s |
| 单次请求 IPC 往返开销 | < 5ms |
| 万条历史列表滚动 | 60fps（虚拟列表） |
| 脚本沙箱启动 | < 20ms（VM 池复用） |
| Runner 100 请求串行 | 开销 < 请求耗时本身 +10% |

## 6. 安全边界

- 渲染进程无 `nodeIntegration`，Preload 仅暴露 `invoke/on` 白名单。
- 用户脚本沙箱：无文件系统、无网络直连（只能走 `toapi.request`，受同一伪装/代理管道管控）、CPU/内存熔断（默认 5s / 128MB，可配）。
- Python 案例子进程：与 JS 沙箱同等约束 —— 网络必经主进程桥接，子进程环境剥离敏感 env，watchdog 超时强杀（详见 09 号文档）。
- SQLite 文件放 `userData/toapi.db`，不加密（本地工具），但提供"导出不带 Cookie/敏感变量"的分享选项（`.tapi` 导出默认剔除 `secret=1` 变量，见 08 号文档）。
