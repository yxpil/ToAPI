# ToAPI — AI 能力集成规范（OpenAI 兼容接口）

> ToAPI 内置 AI 助手：**OpenAI 兼容协议**接入任意模型（OpenAI / DeepSeek / 通义 /
> 本地 Ollama），为接口调试与测试全流程提供生成与分析能力。
> 与 11 号文档的关系：MCP 是"外部 AI 调 ToAPI"，本文档是"ToAPI 内置 AI 帮用户"。

## 1. 模型接入

### 1.1 Provider 配置
| 字段 | 说明 |
|---|---|
| base_url | OpenAI 兼容端点，如 `https://api.openai.com/v1`、`http://127.0.0.1:11434/v1`（Ollama） |
| api_key | 存为全局 secret 变量 `ai.api_key`（掩码、导出剔除、任何通道不出明文，沿用现有 secret 体系） |
| model | 默认 `gpt-4o-mini` 档位；可填任意模型名 |
| timeout / max_tokens | 默认 30s / 2048 |

预设下拉：OpenAI、DeepSeek、通义千问（DashScope 兼容模式）、Moonshot、Ollama（本地，信创/断网环境首选）、自定义。配置页提供「测试连接」按钮（发一条最小 chat 请求验证）。

### 1.2 硬规则
- **默认关闭**，用户显式配置并开启后 AI 功能出现；未配置时 UI 只显示一个 Ghost 按钮引导设置。
- **生成物一律落草稿**：AI 生成的接口/脚本/断言进入待确认状态，用户点「采纳」才生效，永不静默覆盖用户内容（与 09 号文档三路合并原则一致）。
- **发送前脱敏**：组 prompt 时扫描上下文，`secret=1` 变量值替换为 `***`；响应体可配「不发送给 AI」（只发结构与断言结果）。
- **可审计**：每次 AI 调用写 `ai_call_log`（feature、model、token 用量、耗时、是否采纳），设置页可回看。
- 断网/无 key 时所有 AI 功能优雅降级隐藏，不影响核心流程。

## 2. AI 功能清单

### 2.1 自然语言 → 接口草稿（`ai.gen-api`）
输入「查询订单列表，按创建时间倒序分页」→ 结合当前项目环境变量与已有接口风格，生成 ApiDetail 草稿（method/url/params/headers 建议），置信度标注，进待确认区。

### 2.2 自然语言 → 脚本/断言（`ai.gen-script`）
在脚本编辑器内联唤起（`Ctrl+I`）：「每次请求带上 md5 签名，规则是 password+时间戳」→ 生成 pre_script 草稿；「断言返回的订单金额等于请求金额」→ 生成断言草稿。生成代码必须符合 05 号文档沙箱 API（prompt 内嵌 `toapi.*` 契约摘要）。

### 2.3 失败分析（`ai.explain-failure`）
Runner/案例失败后一键「分析」：输入为失败断言 + 请求/响应摘要（脱敏后）→ 输出归因假设（鉴权过期/字段缺失/服务端变更…）与建议下一步，附在报告与通知中心条目里。

### 2.4 MD 解读增强（`ai.interpret-md`）
10 号文档 §2 规则引擎的低置信度片段，可选交给 AI 兜底解析，产出仍走置信度标注与人工确认流程；未开启 AI 时低置信度行为不变。

### 2.5 压测报告解读（`ai.explain-load`）
压测完成后生成自然语言摘要：瓶颈分位、错误聚集时间段、与上次 run 的回归点、调优建议，写入 HTML 报告头部。

### 2.6 响应 Schema 推断（`ai.gen-schema`）
从真实响应推断 JSON Schema → 生成结构断言草稿（字段存在性 + 类型），供「生成测试」增强（09 号文档 §5.1 的 AI 增强模式）。

## 3. 上下文组装规范

| 输入 | 规则 |
|---|---|
| 系统 prompt | 内置，含 ToAPI 脚本 API 契约、药丸 UI 无关、输出格式约束（严格 JSON 草稿） |
| 项目上下文 | 环境变量名（不含 secret 值）、集合内接口名与方法清单（供风格对齐） |
| 当前对象 | 接口定义/响应摘要；响应体超 8KB 截断并标注 |
| 输出解析 | JSON 优先，解析失败降级展示原文并标记「需人工整理」；AI 输出永不直接进沙箱执行 |

## 4. 数据结构（追加进 03 号文档）

- `ai_call_log(id, feature, model, prompt_tokens, completion_tokens, adopted INTEGER, time_ms, created_at)`，保留最近 2000 条。
- Provider 配置存 `app_settings` 的 `ai.provider` 键；`api_key` 不落此表，走全局 secret 变量。

## 5. IPC（追加进 04 号文档 §3.5）

| Channel | 说明 |
|---|---|
| `ai:get-config / ai:set-config / ai:test-connection` | Provider 管理 |
| `ai:gen-api / ai:gen-script / ai:gen-schema` | 生成类（返回草稿，不落库） |
| `ai:explain-failure / ai:explain-load / ai:interpret-md` | 分析类 |
| `ai:adopt` | 草稿采纳（写库，记录 `adopted=1`） |
| `ai:call-log` | 审计回看 |

## 6. 测试用例（纳入 07 号文档执行清单 §2.13）

- Provider：OpenAI 兼容 mock server 验证请求格式；错误 key/超时/限流的错误态展示
- 脱敏：含 secret 值上下文组 prompt 后扫描无明文（用 secret 值做断言扫描）
- 草稿流：生成→采纳→入库；不采纳不留痕（除 ai_call_log）；AI 输出绝不直接执行
- 降级：未配置/断网时 AI 入口隐藏，核心流程无回归
- 本地模型：Ollama mock 验证离线链路（信创场景）
- 审计：每次调用有 log，token 用量累计展示

## 7. 成本与限额

- 设置页显示本月 token 用量（按 `ai_call_log` 聚合）。
- 可配月度 token 上限，超限弹提示并暂停 AI 功能（防失控烧钱）。
- 批量场景（如对整个集合跑失败分析）逐条执行并显示进度，可中途取消。
