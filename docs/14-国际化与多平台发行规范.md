# ToAPI — 国际化、许可与多平台发行规范

> 三部分：① 多语言（随系统自动识别）；② 安装许可条例（EULA，多语言）；
> ③ 多平台发行矩阵（Windows / macOS / 各 Linux 发行版 / 国产 OS / 国产芯片）。

## 1. 多语言（i18n）

### 1.1 语言清单与识别
| 语言 | 代码 | 说明 |
|---|---|---|
| 简体中文 | `zh-CN` | 默认回退语言 |
| English | `en` | |
| 日本語 | `ja` | |
| 繁體中文 | `zh-TW` | |

- 启动时读 OS locale（`app.getLocale()`）自动切换；设置中可手动覆盖，选择持久化。
- 识别不到 → 回退 `zh-CN`。**回退链**：`zh-Hant-HK → zh-TW → zh-CN`，`en-* → en`，其他 → `zh-CN`。
- 所有 UI 字符串走 `t('key')`，禁止硬编码中文进组件；locale 文件 `src/i18n/{lang}.json`，key 即中文原文（如 `t('发送')`），缺失 key 构建期报错。

### 1.2 本地化细则
- 日期/数字/字节大小用 `Intl` 按当前语言格式化。
- 等宽区（URL、代码、响应体）不做本地化排版处理；CJK 字体回退链内置（PingFang / Microsoft YaHei / Noto Sans CJK），Linux 无中文字体时提示安装 `fonts-noto-cjk`。
- 文档型内容（内置帮助、示例脚本注释）随语言切换；用户数据（接口名、断言名）永不翻译。

## 2. 安装许可条例（EULA）

- 安装器首屏与首次启动展示 EULA，语言跟随 §1 识别结果，可手动切换。
- 接受记录存 `app_settings`：`eula_accepted = {version, ts, lang}`；**EULA 版本升级需重新接受**（版本号比对，内容变更即升 minor）。
- EULA 文本随应用打包：`resources/eula/{lang}.md`；安装器（NSIS/Inno 系）与首启共用同一文本源，避免两处漂移。
- 要点条款（占位，法务定稿前骨架）：本地工具数据不出机、开放通道默认关闭、压测功能使用授权责任声明（引用 13 号文档 §1.5）、第三方组件许可证清单（Electron/SQLite 等，随包附 `THIRD_PARTY_LICENSES.txt`）。

## 3. 多平台发行矩阵

### 3.1 平台 × 架构 × 包格式

| 平台 | 架构 | 包格式 | 优先级 |
|---|---|---|---|
| Windows | x64 | NSIS 安装包（含 EULA 页）、便携 zip | P0 |
| Windows | arm64 | NSIS | P1 |
| macOS | universal（Intel + Apple Silicon） | dmg / zip，公证（notarize） | P0 |
| Linux 主流 | x64 | AppImage、deb、rpm、tar.gz | P0 |
| Linux 主流 | arm64 | AppImage、deb、rpm | P1 |
| 国产 OS（统信 UOS / 银河麒麟 / Deepin） | x64 / arm64 | deb（进其应用商店格式要求另行适配） | P1 |
| 国产芯片：龙芯 | loong64 | deb / tar.gz | P2（见 §3.2 风险） |
| 国产芯片：鲲鹏/飞腾（ARM 系） | arm64 | 复用 arm64 包 | P1 |
| 国产芯片：兆芯/海光（x86 系） | x64 | 复用 x64 包 | P0 复用 |

### 3.2 国产芯片风险与对策（关键工程决策）
| 风险 | 对策 |
|---|---|
| Electron 官方无 loong64 构建 | 使用龙芯社区维护的 Electron loong64 分支；该目标单独 CI job，版本可能滞后主线，发布说明中标注 |
| 原生模块需逐架构预编译 | 当前主链路零原生依赖（`node:sqlite` + `worker_threads`/`node:vm`），loong64 主要受 Electron 分支限制；若 B3 引入 gRPC/MQTT 原生加速，必须提供 prebuild 矩阵（x64/arm64/loong64），无 prebuild 的架构在 CI 内源码编译，失败即阻塞该架构发版 |
| 国产 OS 桌面环境差异（UKUI/DDE） | 窗口装饰走系统原生（不 frameless，仅 Windows 用自绘标题栏，见 06 号文档 §4），托盘/通知逐平台冒烟 |
| 缺少实体机 | CI 用 QEMU + 龙芯/UOS 云镜像跑冒烟（启动、发请求、SQLite 读写），UI 细测靠社区反馈 |

### 3.3 构建与发布管线
- electron-builder 矩阵打包；CI（GitHub Actions 或自建 runner）按 §3.1 出包。
- 签名：Windows Authenticode、macOS 公证；Linux 包提供 sha256 校验文件 + GPG 签名。
- 自动更新：Windows/macOS 走 electron-updater；Linux AppImage 走内置更新器，deb/rpm 提示走包管理器或下载页；国产商店渠道按商店机制更新。
- 每架构发版门禁：冒烟用例（冷启动、发送请求、SQLite 迁移、Runner 跑通）全绿才上传。

### 3.4 实现状态（2026-10-24，v0.4.1 起）

| 规范条目 | 状态 | 实测说明 |
|---|---|---|
| §3.1 Windows x64 NSIS + zip | 已实现 | `windows-latest` 出包 + 本平台 e2e + 产物冒烟 |
| §3.1 Linux x64 AppImage / deb / rpm / tar.gz | 已实现 | `ubuntu-22.04` 四包齐出；AppImage 在 CI 容器里用 `APPIMAGE_EXTRACT_AND_RUN=1` 冒烟（无 FUSE）；deb/rpm 依赖 builder 自取的 fpm |
| §3.1 macOS dmg / zip | 部分实现 | 只出 **arm64**（`macos-14`）；Intel x86_64 与 universal 待补 runner |
| §3.1 Windows arm64、Linux arm64 | 未实现 | 需 `--arm64` 目标与对应冒烟环境 |
| §3.1 国产 OS（UOS/麒麟）deb | 未实现 | 目前只有 x86_64 的 deb/rpm，未在真机 UOS/麒麟上冒烟 |
| §3.2 龙芯 loong64 | 未实现 | 依赖社区 Electron loong64 分支，QEMU 冒烟环境尚未搭 |
| 签名与公证 | 未实现 | 无 Authenticode 证书与 Apple 开发者账号 → 产物未签名未公证；Release 说明与 README 明确写出首次运行的绕过方式，不假装可用 |
| GPG 签名 | 未实现 | 只出 `sha256sums.txt` |
| electron-updater 自动更新 | 未实现 | 发版仍靠下载页；`--publish never` 显式关闭 builder 的隐式发布 |
| §1 四语言 i18n | 未实现 | 界面当前全中文硬编码，`src/i18n/` 与 `t()` 尚未落地 |
| §2 版本化 EULA | 未实现 | 安装器无 EULA 页，`app_settings` 无接受记录 |
| 平台差异：窗口装饰 | 已实现 | 仅 Windows `frame:false` + 自绘标题栏；Linux/macOS 原生装饰，e2e 断言"非 Windows 不出现自绘标题栏" |
| 平台差异：托盘驻留默认值 | 已实现 | `closeToTraySupported(platform)`：Windows/macOS 默认开，**Linux 默认关**（GNOME 等常无可用托盘，默认隐藏窗口等于把应用藏没）；用户仍可在通知设置里打开 |
| 平台差异：macOS 隐藏后定时器 | 已实现 | 收进托盘时 `powerSaveBlocker.start('prevent-app-suspension')`，唤回窗口/销毁托盘时释放。macOS runner 的 e2e 首先暴露：`win.hide()` 后系统对应用做 App Nap，主进程定时器被降频，"关窗继续跑定时任务"在 mac 上不成立 |

流水线落点：`.github/workflows/pr.yml`（ubuntu + windows 双平台 `npm run gate` + CLI 自举）、
`.github/workflows/release.yml`（三平台矩阵：本平台测试 → golden-path e2e → 打包 → 产物冒烟 → 汇总 `sha256sums.txt` → 上传 Release）。
`nightly.yml`（22 号文档 §3.2 的夜间全套）尚未落地。

### 3.4 平台适配细则
- 路径：一律 `app.getPath('userData')`，禁止拼接 `C:\` 或 `~`。
- 行尾/编码：TAPI 与 MD 文件统一 UTF-8 + LF（Windows 上写出也 LF，导入兼容 CRLF）。
- 字体与输入法：Linux CJK 回退链；所有输入框验证 IME 组合输入不被 Enter 误提交（composition 事件守卫）。
- 高 DPI：Windows 150%/200% 缩放与 Linux 分数缩放下药丸控件不虚边（SVG 图标天然免疫）。

## 4. 测试（用例纳入 07 号文档执行清单 §2.11）

- i18n：四种语言全 key 覆盖（构建期 lint）；回退链正确；切换语言无需重启生效
- EULA：首次启动必现；版本升级后重新要求接受；拒绝则退出应用
- 平台：每包冒烟（启动/请求/DB/Runner）；龙芯与 UOS 在 QEMU/云镜像跑通冒烟
- 输入法：中文输入法组合态下按 Enter 不误触发发送
- 文件互操作：Windows 导出的 .tapi 在 Linux/macOS 导入逐字节一致（编码与行尾）
