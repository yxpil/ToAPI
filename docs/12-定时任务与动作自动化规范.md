# ToAPI — 定时任务与动作自动化规范

> 两类定时能力：
> ① **定时测试** —— cron/间隔触发集合 Runner、案例、MD 文档测试（监控式回归）；
> ② **定时动作** —— 录制/编排的界面操作宏，定时自动执行（开项目、切环境、填参数、点发送、导报告）。

## 1. 定时任务模型

新表 `schedule_task`：
| 列 | 说明 |
|---|---|
| id / name / enabled | 常规 |
| target_type | `'collection' / 'case' / 'mddoc' / 'api' / 'macro'` |
| target_id | 目标对象 id（macro 指向 `action_macro`） |
| schedule | `{kind:'cron', expr:'0 */30 * * * *'} \| {kind:'interval', everyMs}` \| `{kind:'once', at}` |
| env_id | 锁定环境（定时回归必须锁环境，禁止跟随当前激活） |
| overlap_policy | `'skip' / 'queue' / 'parallel'`，默认 skip |
| misfire_policy | 应用未运行错过触发点时：`'run-on-launch' / 'skip'`，默认 run-on-launch（仅补最近一次） |
| notify | `{onSuccess:bool, onFail:bool, report:'none'\|'json'\|'junit'\|'html'}`：成功是否打扰、失败是否打扰、每次触发是否落一份报告文件（报告绝对路径写进通知正文，15 号文档 §1） |
| last_run_at / last_run_id / next_run_at | 运行状态缓存 |

- 调度器在主进程：`node-cron` 风格解析器自实现（避免依赖），毫秒不必要，秒级即可。
- 每次触发等价于一次 `runner:start`，结果进 `runner_run`，UI「任务」面板可见下次/上次运行与通过率。
- cron 编辑器：输入表达式实时显示**未来 5 次触发时间**（人类可读），非法表达式即时报错。

## 2. 应用未运行时：系统级唤醒（可选）

| 平台 | 机制 |
|---|---|
| Windows | 注册任务计划程序（Task Scheduler）：`ToAPI.exe --run-task=<id> --headless` |
| macOS | launchd agent |
| Linux | systemd user timer / crontab 行 |

- 用户在任务上勾选「应用关闭时也运行」后注册对应系统项；卸载/删除任务时同步清除。
- 无头运行完成后写 `runner_run`，下次开 GUI 时弹汇总 Toast。
- 默认不开：纯应用内调度已覆盖"工具常开"的测试机场景。

## 3. 动作宏（定时界面操作）

### 3.1 用途与边界
为重复性界面操作服务：每天 9 点切到 prod 环境、跑冒烟集合、导出报告到指定目录。**不是**通用 RPA——宏只能操作 ToAPI 自身窗口内对象，不支持操作系统级点击。

### 3.2 步骤模型
`action_macro(id, name, steps_json, created_at, updated_at)`，steps 为有序数组：

```jsonc
[
  {"op": "open-project", "target": {"projectId": "..."}},
  {"op": "activate-env", "target": {"envId": "..."}},
  {"op": "open-api", "target": {"apiId": "..."}},
  {"op": "set-field", "target": {"zone": "params", "key": "page"}, "value": "3"},
  {"op": "click", "target": {"control": "send"}},          // 仅限白名单控件
  {"op": "wait", "ms": 1000},
  {"op": "wait-response", "timeoutMs": 30000},
  {"op": "export-report", "target": {"runId": "latest"}, "path": "D:/reports"},
  {"op": "assert-last-run", "expect": {"failed": 0}}
]
```

| 规则 | 说明 |
|---|---|
| 控件白名单 | `click` 只允许：send、run、save、tab 切换；**禁止**点击删除/清空/确认弹窗（除非步骤带 `"allowDanger": true` 且宏保存时二次确认） |
| 录制生成 | 「开始录制」后用户在 UI 的白名单操作自动转为步骤，可再编辑参数 |
| 失败策略 | 任一步骤失败默认中止并标记宏失败；可配 `continueOnError` |
| 幂等提醒 | 宏编辑器对"非幂等步骤"（如 set-field 覆盖已改内容）显示提示条 |

### 3.3 执行与观测
- 宏可由定时任务触发（`target_type='macro'`）或手动运行；运行过程在「任务」面板逐步骤显示状态（SVG check/cross/spinner）。
- 宏运行产物（触发的请求/runner_run）与手动操作同库同历史，可回溯。

## 4. IPC（追加进 04 号文档 §3.5）

| Channel | 说明 |
|---|---|
| `task:list / task:create / task:update / task:delete / task:toggle` | 定时任务 CRUD |
| `task:preview` | `{schedule}` → 未来 5 次触发时间 |
| `task:run-now` | 立即触发一次（不走 overlap 排队） |
| `task:system-register / task:system-unregister` | 系统级唤醒注册/注销 |
| `macro:list / macro:save / macro:run / macro:record-start / macro:record-stop` | 动作宏 |

## 5. 测试用例（纳入 07 号文档执行清单 §2.9）

- cron 解析：合法/非法表达式、时区固定为本机、跨天/跨月触发正确
- overlap：skip 时上次未结束不并发；queue 时排队且上限 3
- misfire：关机错过 3 次触发，启动后只补最近一次
- 系统级：注册后杀进程重启验证系统项存在；删除任务后系统项清除（三平台冒烟）
- 宏：白名单外控件拒绝生成步骤；`allowDanger` 缺省时危险点击被阻断；录制→回放步骤一致
- 时钟：手动改系统时间后调度不重复触发（以单调时钟为准，墙钟只用于展示）

实现落点：`electron/schedule/cron.ts`（解析与下次触发计算，无第三方依赖）、`electron/schedule/service.ts`（CRUD + 调度循环 + overlap/misfire + 完成汇报）。
用例覆盖见 `tests/unit/schedule/cron.test.ts`（13 例，含 2 月 30 日永不触发、日/周并集语义、跨周末工作日）与
`tests/integration/schedule/{scheduler,tasks}.test.ts`（22 例：skip/queue 上限 3/parallel、misfire 只补最近一次、墙钟拨快不提前触发、目标删除后自动停用、run-now 走真实靶场并落报告）。

## 6. 实现状态

| 规范条目 | 状态 | 说明 |
|---|---|---|
| §1 cron / interval / once 三种触发 | 已实现 | 5 段或 6 段表达式（6 段首字段为秒），本机时区；interval 以 epoch 对齐避免漂移 |
| §1 锁环境、overlap、misfire、notify 四列 | 已实现 | `envId` 缺失或不属于目标项目直接 `VALIDATION`；misfire=run-on-launch 只补最近一次并 warn |
| §1 未来 5 次触发预览 | 已实现 | `task:preview` 返回时间数组 + 非法表达式的中文原因，编辑器实时刷新 |
| §1 target_type=`collection`/`project`/`api` | 已实现 | 等价一次 `runner:start`，结果照常进 `runner_run` |
| §1 target_type=`case`/`mddoc` | 未实现 | 案例运行器（09 号文档）与 MD 文档测试（10 号文档）本身尚未落地，落地后补枚举即可 |
| §1 target_type=`macro` 与 §3 动作宏 | 未实现 | `action_macro` 表、录制、白名单控件回放均未开工 |
| §2 系统级唤醒（Task Scheduler / launchd / systemd） | 未实现 | `task:system-register` / `task:system-unregister` 未落地；当前只在应用运行期间调度，托盘驻留（15 号文档 §4）已覆盖"进程不退出"的常见场景 |
| §4 `task:*` 七个通道 | 已实现 | 见 04 号文档 §3.5 |
| §5 单调时钟 | 已实现 | 到期判定用 `process.hrtime`，墙钟只用于展示与排期换算；库里 `next_run_at` 与内存排期不一致时自动重新对齐（跨实例编辑同一库也不会重复触发） |
