# ToAPI — MD 文档解读与文档内测试规范

> 两个方向的能力：
> ① **解读**任意 Markdown 接口文档 → 自动提取接口定义，生成可调试的接口草稿；
> ② **MD 文档内做测试** —— 一种可执行的 Markdown 测试格式（`.tapi.md`），
> 文档本身就是测试套件，可运行、可断言、可与 App 内集合双向同步。

## 1. 能力总览

```
任意 API 文档.md ──解读──▶ 接口草稿（可入库）
.tapi.md 测试文档 ──运行──▶ 逐块执行 + 断言 + 报告
.tapi.md 测试文档 ◀─同步─▶ App 内集合（双向）
```

| 场景 | 用法 |
|---|---|
| 研发给了一份 MD 接口文档 | 「解读文档」→ 自动识别端点/参数/示例 → 一键建项目 |
| 测试部想要"看得懂又能跑"的用例 | 写 `.tapi.md`，App 打开即跑，结果标注在文档边栏 |
| 跨部门交付 | 集合导出为 `.tapi.md`，对方无 App 也能读，有 App 就能跑 |

## 2. MD 解读（任意文档 → 接口草稿）

### 2.1 识别规则（按优先级，命中即生成草稿）

| 规则 | 示例 | 提取结果 |
|---|---|---|
| 行内端点模式 | `` `POST /api/orders` ``、`GET https://api.example.com/users` | method + url |
| http 代码块 | ```` ```http ```` 块内 `POST /login HTTP/1.1` + 头 + 体 | 完整请求 |
| curl 代码块 | ```` ```bash ```` 内含 `curl -X POST ...` | 复用 codegen 的 curl 解析 |
| 参数表格 | 紧邻端点后的 `\| 参数 \| 类型 \| 必填 \| 说明 \|` 表 | query/body 字段清单 + 注释 |
| 响应示例块 | 标题含「响应/Response/返回」的 ```` ```json ```` | 存为接口示例，并可触发"生成断言" |
| 标题层级 | `## 订单相关` 下所有端点 | 映射为同名集合 |

### 2.2 解读结果与人工确认

- 每个端点生成 ApiDetail 草稿，附**置信度**（高=代码块完整请求；中=端点+参数表；低=仅一行端点）。
- 预览面板按置信度分组展示，低置信度默认不勾选；参数表格只生成"字段注释"，不猜必填与类型（无法确定时留空并在 UI 标黄）。
- 标题层级 → 集合嵌套；文档标题 → 项目名；文档中的"环境/域名"段落识别为环境变量建议（如识别到多个 host 出现频次，建议建 `baseUrl` 变量）。
- **永不静默猜测**：解析不出的片段保留原文进接口描述，列表里标记"含未解析内容"。

### 2.3 IPC
| Channel | 入参 | 返回 |
|---|---|---|
| `md:interpret` | `{filePath}` 或 `{content}` | `{drafts: [{api, confidence, sourceLine}], envSuggestions, unparsedBlocks}` |

## 3. `.tapi.md` 可执行测试文档格式

### 3.1 文件骨架

```markdown
---
format: tapi-md
version: "1.0"
env: staging            # 锁定环境（可选）
---

# 订单链路回归

## 1. 登录

<!-- @request id=login -->
```http
POST {{baseUrl}}/api/login
Content-Type: application/json

{"username": "{{username}}", "password": "{{password}}"}
```

- [assert] status == 200
- [assert] body.data.token isDefined
- [extract] token = jsonpath($.data.token) -> runtime
- [assert] timeMs < 1500

## 2. 创建订单

<!-- @request id=create-order depends=login -->
```http
POST {{baseUrl}}/api/orders
Authorization: Bearer {{token}}
Content-Type: application/json

{"sku": "A-001", "count": 1}
```

- [assert] status == 201
- [extract] orderId = jsonpath($.data.id) -> runtime
```

### 3.2 指令语法

| 指令 | 位置 | 语义 |
|---|---|---|
| `<!-- @request id=X depends=a,b -->` | http 代码块前一行的 HTML 注释 | 声明请求块：id（块内唯一）、依赖（控制执行顺序，默认按文档顺序） |
| `[assert] <表达式>` | 请求块后的列表项 | 断言，表达式子集见 §3.3 |
| `[extract] name = jsonpath(...) -> runtime\|env\|global` | 同上 | 提取器，等价于接口提取器 |
| `[fake] ua=@preset:okhttp` / `[fake] proxy=...` | 同上 | 块级伪装，等价于 api.fake |
| `[script] ```js ... ``` ` | 请求块后 | 内联 pre/post 脚本（JS，进同一沙箱） |
| frontmatter `env` | 文件头 | 锁定环境；无则跟随当前激活环境 |

### 3.3 断言表达式子集（刻意小而确定）

```
status == 200 | status in [200,201]
header.content-type contains "application/json"
body.<jsonpath简写> == "x" | isDefined | matches /regex/ | > < >= < <=
timeMs < 2000
```
不支持任意 JS 表达式 —— 文档断言必须让非研发读者一眼看懂；复杂逻辑走 `[script]` 块。

## 4. 文档内运行（MD Runner）

- 打开 `.tapi.md` 进入**文档视图**：左侧渲染文档，右侧（或可折叠的行间距区）显示每块运行结果。
- 执行模型：按依赖拓扑串行执行；共享运行时变量；`depends` 失败则下游标记 SKIPPED。
- 结果呈现（遵守 06 号 UI 规范，图标全部 SVG）：
  - 通过：请求块标题行右侧黑色描边小药丸内嵌 SVG check 图标 + 耗时
  - 失败：同位置红色描边药丸 + SVG cross 图标，点击展开失败断言明细
  - 未运行/被跳过：灰色描边药丸 + SVG dash 图标
  - **文档原文永不被修改**，结果只在渲染层叠加。
- 单块可单独重跑（hover 出现药丸按钮）；全文一键运行等价于 `runner:start`。

## 5. 双向同步

| 方向 | 行为 |
|---|---|
| `.tapi.md` → App | 解析为项目/集合/接口（含提取器、伪装、断言），文件路径记录在 `md_document` 表 |
| App → `.tapi.md` | 集合右键「导出为 MD 测试文档」，断言转 `[assert]` 指令，post_script 转 `[script]` 块 |
| 冲突 | 文件 mtime/hash 变化时提示：以文件为准重载 / 以 App 为准覆盖导出。无静默双向合并 |

往返等价要求与 09 号文档 §5.3 相同：`.tapi.md → App → .tapi.md` 后请求块、断言、提取器语义一致（排版可差异）。

## 7. 测试用例（追加进 07 号文档 §2.7）

- 解读：五类识别规则各有正负用例；低置信度默认不勾选；参数表不猜类型
- 解析：frontmatter 缺失/非法版本报错；`depends` 成环检测拒绝运行；未知指令警告不中断
- 运行：拓扑顺序正确；提取→下游引用链路通；断言失败下游 SKIPPED
- 同步：往返等价快照；外部改文件后 sync_state 流转正确；覆盖导出有确认弹窗
- 安全：MD 内 `[script]` 块与接口脚本同沙箱同熔断；MD 渲染禁 HTML 注入（白名单渲染，`<script>`/事件属性剥离）
