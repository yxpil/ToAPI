# ToAPI — 产品规划

> 一款简约、可脚本化、面向自动化测试与一般接口调试的桌面 API 请求工具。
> Electron + SQLite，浅灰画布上漂浮白色面板，药丸控件与下划线 Tab 的极简设计。

---

## 1. 产品定位

| 维度 | 说明 |
|---|---|
| 产品名 | ToAPI |
| 形态 | Windows 桌面应用（Electron） |
| 目标用户 | 开发者 / 测试工程师，需要"发请求 + 写脚本 + 跑自动化"一体化工具 |
| 核心差异 | 内置 JS 脚本引擎（前置/后置/伪装/联调），本地 SQLite 全量存储，无账号无云同步，启动即用；**Postman 本地全量兼容**（Collection v2.1 / Environment / `pm.*`，见 23 号文档） |
| 不做的事 | 不做团队协作云端同步、不做插件市场、不做重型 Mock Server 集群 |

## 2. 核心需求场景

1. **一般接口请求**：快速构造 HTTP/HTTPS 请求，查看格式化响应。
2. **自动化参数携带**：通过 JS 脚本在请求前动态生成签名、Token、时间戳、加密 Body。
3. **请求伪装**：自定义 User-Agent、Header 伪装、代理、TLS 指纹层级的超时/重定向控制。
4. **联合请求（链式调用）**：接口 A 的响应提取字段 → 注入接口 B 的参数，支持串行流程与变量共享。
5. **自动化测试**：断言脚本 + 批量执行 + 报告导出。
6. **分类管理**：项目 → 集合 → 接口 三级组织，跨项目复用环境变量。
7. **跨部门协作**：`.tapi` 单文件导入导出（敏感变量可剔除/加密），接口一键生成 JS / Python / cURL 案例代码，案例代码与真实响应可自动转换为测试断言。
8. **文档即测试**：解读任意 Markdown 接口文档生成接口草稿；`.tapi.md` 可执行测试文档 —— 文档内声明请求/断言/提取，打开即跑，与集合双向同步（详见 10 号文档）。
9. **开放给 AI 与程序**：Local HTTP API 供脚本/CI 驱动；内嵌 MCP Server 让 AI 助手直接调用接口与 Runner；导出 MD Skill 包让无 MCP 的 AI 照着说明书调用（详见 11 号文档）。
10. **定时与压测**：cron/间隔定时跑集合、案例、MD 测试；动作宏录制回放界面操作；单机压测（VU/RPS/分位数/阈值判定）；能力对齐主流 API 工具（详见 12 / 13 号文档）。
11. **消息通知**：测试/定时任务/压测完成即提醒 —— 应用内 Toast + 通知中心留痕 + 后台托盘 OS 通知 + Webhook 群机器人推送，按事件类型订阅、聚合防轰炸（详见 15 号文档）。
12. **内置 AI 助手**：OpenAI 兼容协议接入任意模型（含本地 Ollama），自然语言生成接口/脚本/断言、失败归因分析、MD 解读兜底、压测报告解读；生成物一律草稿待采纳、secret 脱敏、全程可审计（详见 16 号文档）。
13. **多语言与多平台**：中/英/日/繁随系统自动识别；安装许可条例（EULA）版本化；发行覆盖 Windows/macOS/Linux 各发行版、国产 OS（UOS/麒麟/Deepin）与国产芯片（龙芯/ARM/x86 系，详见 14 号文档）。
14. **局域网协作与多机联合**：填目标主机 IP + 口令配对另一台 ToAPI，加密信道下互传项目、指定机器代为测试、多台机器联合跑回归与联合压测；全程局域网直连，不经服务器、密钥值不跨机（详见 24 号文档）。

## 3. 功能清单与优先级

### P0（MVP 必须）
- 项目 / 集合 / 接口 三级树管理（增删改、拖拽排序）
- 完整请求编辑器：Method / URL / Params / Headers / Body（json、form、raw、binary）
- 响应查看器：Pretty JSON / Raw / Headers / Cookie / 耗时 / 大小
- 环境变量与全局变量（`{{var}}` 插值）
- SQLite 持久化，启动 < 1.5s 冷加载
- 请求历史记录

### P1（核心差异化）
- JS 脚本引擎：Pre-request Script / Post-response Script / Test Assertion
- 脚本内 API：`toapi.request()` 发起联合请求、`toapi.env.set/get`、`toapi.fake.*` 伪装库
- 链式请求编排（可视化顺序 + 变量提取器 JSONPath/正则）
- 伪装面板：UA 库、Header 模板、代理配置、Cookie Jar
- 批量执行器：集合级 Runner + 断言统计 + 失败重试

### P2（体验增强）
- **TAPI 文件互传（已实现）**：项目或集合子集导出为 `.tapi` 单文件，敏感变量默认剔除（可选明文携带），导入支持新建 / 合并两种策略、接口按「方法+URL+名称」判重、checksum 校验与全程事务回滚；`toapi run project.tapi` 可在 CI 里直接跑（详见 08 号文档 §9 实现状态；加密携带、`payload.cases` 与拖拽导入仍未实现）
- **多语言案例**：JS / Python 双语言案例编写与运行（Python 经子进程桥接走同一 HttpEngine，详见 09 号文档）
- **案例代码生成**：接口一键生成 cURL / JS / Python 案例代码，可独立运行或回导 App
- **自动转测试**：真实响应一键生成断言脚手架（三路合并不覆盖用户修改）；cURL/JS/Python 代码反向解析为接口定义并建议断言
- **MD 文档解读**：任意 MD 接口文档识别端点/参数表/响应示例，按置信度生成接口草稿
- **MD 文档内测试**：`.tapi.md` 可执行测试文档格式（`[assert]`/`[extract]`/`[fake]` 指令），文档视图内运行并叠加结果，与集合双向同步
- **开放调用（部分已实现）**：Local HTTP API（调用密码、限流、只读+执行子集）与内嵌 MCP Server（stdio / Streamable HTTP 双传输，15 个工具）已落地并可被 AI 客户端直接使用；SKILL.md 说明书由 `toapi_get_skill` / `GET /v1/skill` 交付。**待接**：Skill 包写盘与右键导出、Runner 并发排队、MCP 流式（11 号文档 §9）
- **定时任务**：cron/间隔/单次触发集合 Runner、案例、MD 测试；错过补跑策略；可选系统级唤醒（应用关闭也运行）
- **动作宏**：白名单界面操作录制/编排/回放（开项目→切环境→填参数→发送→导报告），可被定时任务触发
- **单机压测**：VU/加压曲线/RPS 上限/dataFeed 数据驱动/分位数实时曲线/阈值判定/HTML 报告与外网限额闸门
- **消息通知**：通知中心（未读角标、按类型筛选）、后台托盘 + OS 原生通知、Webhook（企业微信/钉钉/飞书预设）、60s 聚合与状态变化模式防轰炸
- **AI 助手**：OpenAI 兼容 Provider（预设 OpenAI/DeepSeek/通义/Ollama）、NL 生成接口与脚本断言、Runner 失败归因、压测报告解读、月度 token 限额
- cURL 导入 / 导出
- 接口复制、跨项目移动
- 测试报告导出（HTML / JSON）
- 快捷键体系、命令面板（Ctrl+K）
- **全局搜索**：命令面板即搜索入口，跨项目命中项目 / 接口 / 集合 / 环境，匹配范围含接口名称、方法与 **URL**，回车直接跳转定位（06 号文档 §5）
- **单独重命名**：项目 / 集合 / 接口均可在树里右键重命名，接口名与 URL 相互独立（06 号文档 §3.4）
- 响应 Diff、响应保存为示例

### P2.5（Postman 本地全量兼容，v0.2.0 – v0.7.0）

> 范围定义与验收见 23 号文档 §9/§10：凡 Postman 单机可完成的能力都要有本地等价物；云账号、工作区、Flows、云 Mock/Monitor 不做。
> 版本映射（2026-10-24 第三次调整）：B1+B2 已随 **v0.2.0** 发布；**v0.3.0 = 协作与开放**（`.tapi` 互传、全局搜索与重命名、AI 可调用面）已发布；**v0.4.0 = 后台运行**（系统托盘驻留、定时回归任务、通知中心与 OS/Webhook 汇报，12 / 15 号文档）；Postman 的 B3/B4 顺延为 v0.5.0/v0.6.0，批次范围与验收不变。
> 版本映射（2026-10-24 第四次调整）：**v0.5.0 = 局域网协作与多机联合的第一段**（节点配对 + 加密信道 + 项目互传 + 代为测试 + 审计，24 号文档 §1–§4/§7–§10），多机联合测试（§5）与联合压测（§6）随后补；Postman 的 B3/B4 再顺延为 **v0.6.0 / v0.7.0**，批次范围与验收标准不变。

- **B1 资产与脚本（v0.2.0，已发布）**：Collection v2.1 / Environment 双向导入导出；集合级 auth / variables / scripts 继承；`pm.*` 脚本兼容；动态变量；lodash / CryptoJS / uuid / moment 沙箱库
- **B2 数据驱动与 CLI（v0.2.0，与 B1 同版发布）**：CSV/JSON 数据文件、多迭代、`pm.iterationData`、`pm.execution.setNextRequest`、`toapi run` 无头 CLI、JUnit/JSON/HTML 报告
- **后台运行（v0.4.0）**：托盘驻留 + 关窗最小化、cron/间隔/单次定时回归、通过率与报告路径进系统通知、通知中心与订阅矩阵、Webhook（企业微信/钉钉/飞书/raw）。动作宏与系统级唤醒（任务计划/launchd/systemd）不在本版，见 12 号文档 §6
- **三平台发行（v0.4.1，已发布）**：Windows x64、Linux x64（AppImage/deb/rpm/tar.gz）、macOS arm64 全部由 GitHub Actions 原生 runner 出包，且每个平台在同一 runner 上跑完 golden-path e2e 与产物冒烟才进 Release；未签名未公证、macOS Intel 与 arm64 架构待补（14 号文档 §3.4）
- **B3 协议扩展（v0.6.0）**：GraphQL、WebSocket、SSE、gRPC、MQTT
- **B4 自动化与长尾（v0.7.0）**：OpenAPI 2.0/3.0/3.1 导入导出、本地 Mock、保存示例、代码生成扩展、`pm.visualizer`、认证长尾（OAuth2/OAuth1/Digest/NTLM/AWS SigV4 等）与客户端证书、**Apifox 资产互操作**（Postman v2.1 / OpenAPI 双桥，原生 JSON 以用户提供真实导出样本为前提，23 号文档 §7.1）

## 4. 里程碑

| 里程碑 | 内容 | 验收标准 |
|---|---|---|
| M1 骨架 | Electron 壳 + SQLite + 三级树 + 基础请求收发 | 能建项目、发 GET/POST JSON、看响应、数据重启不丢 |
| M2 变量与环境 | 环境管理、`{{var}}` 全链路插值、历史记录 | 切换环境后同一接口发出不同 Host |
| M3 脚本引擎 | Pre/Post 脚本 + `toapi` 内置对象 + 沙箱隔离 | 脚本可改请求头、可发子请求、可写断言 |
| M4 联合请求 | 变量提取器 + 链式 Runner | 登录→取 token→带 token 请求 全链路一键跑通 |
| M5 伪装与测试 | UA/Header 模板、代理、批量断言报告 | 集合 Runner 输出通过率，报告可导出 |
| M5.5 协作 | TAPI 导出/导入（剔除密钥）、代码生成、响应转断言 | 导出文件在干净机器导入跑通全链路；`api→code→api` 往返等价 |
| M5.6 开放 | Local API + MCP Server + Skill 包导出 | AI 客户端经 MCP 完成"读项目→发请求→跑集合"；CI 经 HTTP API 跑回归 |
| M6 打磨 | 快捷键、命令面板、性能优化 | 冷启动 <1.5s，万条历史滚动不卡 |
| M7 定时与压测 | 定时任务、动作宏、单机压测 | cron 触发回归入报告；宏回放步骤一致；靶场 200 RPS 分位数准确 |
| M8 国际化与平台化 | 四语言 + EULA + 全平台发行矩阵 | Windows/macOS/Linux 主流包全绿冒烟；UOS/麒麟 deb 跑通；龙芯 QEMU 冒烟 |
| M9 Postman 兼容 | B1 资产与脚本 → B2 数据驱动与 CLI → B3 协议 → B4 自动化长尾 | 真实 Collection 往返语义无损；Postman 脚本示例不改一行跑绿；CLI 退出码可被 CI 判定；五种协议靶场用例全绿；Apifox 导出样本经 Postman/OpenAPI 桥往返无损（23 号文档 §10） |

## 5. 非目标（明确不做）

- 不做云侧协作：登录/注册、云同步、团队工作区、云 Mock/云 Monitor 一律不做 —— 纯本地工具，数据即文件。
  **例外（2026-10-24 修订）**：局域网内两台 ToAPI 直连的配对、项目互传、代为测试与多机联合测试/压测改为支持，
  见 24 号文档；它不引入任何服务器、账号或公网依赖，"数据不出本机所在的局域网"这条不变。
- 不做 Postman 云侧能力（账号、团队工作区、Postman API/Flows/AI Agent、云 Mock/Monitor）—— 只做本地全量兼容（23 号文档 §9）。
- 不做 Apifox 云协作（团队空间、在线文档托管、云端 Mock/定时任务）—— 只做文件资产互操作（B4，23 号文档 §7.1）。
- 不做可视化主题编辑器 —— 只提供一套精心调校的简约主题。
- 不做请求录制器（浏览器抓包）—— 聚焦"构造与自动化"，不做抓包。
- 不做**跨公网/需中继**的分布式压测与插件市场。局域网内多机联合压测改为支持，但排在单机压测引擎之后（13 号文档 §1 → 24 号文档 §6）。

## 6. 候选功能清单（Backlog，评估后入里程碑）

| 候选 | 价值 | 主要成本/风险 |
|---|---|---|
| 响应 Schema 漂移检测（契约守护） | 保存基线 schema，后续响应结构 diff 告警，回归测试利器 | diff 噪音治理（时间戳/ID 字段需忽略规则） |
| OS 钥匙串集成 | secret 变量存系统 keychain（Windows DPAPI/macOS Keychain/libsecret），比 DB 更稳 | 三平台 + Linux 发行版差异；信创平台 libsecret 可用性 |
| 接口依赖图可视化 | 从提取器与 `{{var}}` 引用推导 DAG，链式链路一图看清 | 布局算法；大项目性能 |
| 覆盖率统计 | 项目内"无断言接口/未跑过的接口"清单，补齐测试盲区 | 低 |
| 数据快照对比 | 同一接口两次响应深 diff（忽略路径可配） | 中 |
| WebSocket/gRPC（已列 B3） | 主流工具均有 | WS 较易；gRPC 需反射/proto 管理，重；随 Postman 兼容批次交付（23 号文档 §6） |
| Apifox 原生项目 JSON 解析（已列 B4） | 跨部门混用 Apifox 的团队可直接互转，不必绕 Postman/OpenAPI | 官方未公开 schema，须先拿到用户提供的真实导出样本反推；无样本时只做 Postman/OpenAPI 桥（23 号文档 §7.1） |
| 离线许可激活 | 政企内网分发场景 | 需定义商业模式后再做 |
| 内置 JSONPath/正则测试器 | 提取器编写即时验证 | 低，建议提前到 P2 |

优先级建议：**JSONPath 测试器**与**覆盖率统计**成本低价值高，可提前；**Schema 漂移检测**与定时任务组合就是"接口变更监控"，是差异化亮点，建议进 M7。
