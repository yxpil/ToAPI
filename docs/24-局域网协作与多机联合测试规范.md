# ToAPI — 局域网协作与多机联合测试规范

> 把"另一台机器上的 ToAPI"当成一等公民：**配对、互传项目、指定机器跑（代为测试）、多台机器一起跑（联合测试）、
> 多台机器一起压（联合压测）**。全部只发生在同一局域网内，两台机器之间直连，**不经过任何服务器、不依赖云账号**。
> 本文件是对 01 号文档 §5 与 13 号文档 §2 "不做分布式"这条非目标的**明确修订**：不做的是云侧协作与公网分布式，
> 局域网内点对点联合改为支持。

## 0. 边界与原则

| 原则 | 落地 |
|---|---|
| 只复用已有通道 | 节点就是开了「局域网访问」的 ToAPI 实例，走 11 号文档的 Local HTTP API，不再造一套守护进程 |
| 机器间流量必须加密 | 节点协议 `toapi-node/1` 强制应用层加密（§2）；普通脚本/AI 客户端仍可走明文 loopback |
| 口令即身份 | 配对口令 = 授权凭据；口令强度直接决定加密强度，界面必须把"生成的随机口令"作为默认推荐 |
| 只同步定义，不同步数据 | 项目/集合/接口/脚本/环境定义可互传；**密钥值、历史记录、运行记录、Cookie 永不跨机** |
| 显式同步，不做自动双写 | 拉取/推送是用户动作，带差异预览与冲突选择；不引入 CRDT/向量时钟那套自动复制 |
| 节点不可信也不许伤人 | 每次联合都要用户在 GUI 确认目标清单与范围；越界 host、超并发预算直接拒绝 |
| 失败可降级 | 某台机器掉线只影响它自己那一份：标 `skipped` + warn 通知，其余节点结果照常汇总 |

## 1. 节点模型

新表 `node`：

| 列 | 说明 |
|---|---|
| id / name | 本机起的别名（默认取远端 `hostname`） |
| host / port | 目标 IP 或主机名 + 端口（默认 4730） |
| device_id | 远端实例的稳定标识（首次配对时学到，之后变了要重新确认） |
| channel_key | **配对时由口令派生的信道密钥（scrypt 派生值，非口令明文）**；改口令要重新配对 |
| fingerprint | 由信道密钥算出的校验指纹，配对成功即学到 |
| confirmed_fingerprint | 用户当面核对后锁定的指纹（TOFU）；与当前指纹不一致时拒绝写操作 |
| added_at / last_seen_at / last_error | 探活与故障留痕 |
| seq / epoch | 出站帧序号与防重放轮次：`seq` 落库记住最后用到的值（重启也不回退），每次配对换一个新的 `epoch`，对端按「设备 + 轮次」分序号链 |
| labels | 逗号分隔标签（`staging`、`gpu`、`win`），供选机与压测分片用 |
| enabled | 临时停用而不删除 |

新表 `node_call_log`（审计，与 `external_call_log` 同构）：`id, node_id, peer, action, ok, error_code, time_ms, items, created_at`，
保留最近 5000 条环形清理。`node_id` 为空表示**入站**（别人调本机），此时 `peer` 记来源 `IP:端口`；出站调用的 `peer` 记对端 `deviceId`。
**参数摘要不得含口令、信道密钥与 secret 变量值**（`tests/integration/node/nodes.test.ts` 按此断言）。

本机作为被配对一方的身份走 `app_settings` 的 `node.self`（只有稳定 `deviceId`），
`device_id` 与指纹不落库为对外信息：地址与端口由 11 号文档的 `open.config` 决定，本机指纹在需要时由信道密钥现算（`node:self`）。

## 2. 配对与信道（`toapi-node/1`）

### 2.1 配对流程
1. 被连的机器：设置 → 开放调用 → 勾「局域网」（二次确认）→ 状态变「可被配对」，界面显示 `IP:端口` 与本机设备指纹。
2. 本机：节点面板 → 新增 → 填 `IP[:端口]` + 口令 → 「配对」。
3. 握手（一次明文 HTTP + 一次加密探活）：
   - `GET /v1/node/hello?deviceId=…` 明文回 `{deviceId, salt, protocol, version, platform}`；`salt` 就是开放通道的 scrypt 盐，**不是秘密**，只作 KDF 上下文；
   - 双方各自用 `scrypt(口令, salt, 32B)` 派生 `K`（参数与 11 号文档 `open.config` 完全一致：N=2^14、r=8、p=1，否则两端算不出同一把钥匙），再用 HKDF-SHA256 从 `K` 分出 `req` / `res` 加密子密钥与指纹子密钥；
   - 配对方立刻用 `K` 发一帧加密 `/v1/node/state`：**解得开就算口令正确**，无需另发凭据；这一步同时学到远端 `deviceId` 与项目摘要；
   - 指纹由本机自行按 `K` 算出（明文握手刻意**不回指纹**，否则等于给抓包者一个可离线验证口令的判据）。
     **首次见到该指纹时界面给"确认指纹"按钮**，让用户核对两屏一致（防拿到口令的中间人冒充）；确认后写入 `confirmed_fingerprint`，之后不匹配直接拒绝写操作且不降级。
   - 不做临时密钥交换（X25519/ECDH）：口令就是预共享密钥，信道强度上限由口令决定，握手再加一轮只会推迟同一个结论；界面因此强制提示弱口令。
4. 口令正确但指纹变化 → 判为"对端身份变了"，拒绝执行任何写操作，只允许只读探测并红字提示。

### 2.2 信道约束
- 之后所有请求体与响应体都走 `AES-256-GCM(HKDF(K, dir), iv 每次随机)`，`x-toapi-node: 1` 头标识；AAD 绑成 `toapi-node-v1|req|seq|path`，所以**换方向或换路径都解不开**；
- 帧里带 `seq`，接收端按「`deviceId` + `epoch`」分链校验严格递增，回退或重复一律拒绝（防重放）；`epoch` 每次配对重新生成，重新配对不会因为旧链记着大序号而被自己锁死；
- 明文 HTTP 端口上**只有** `/v1/node/*` 接受该协议；未加密的节点请求一律 `400`（`节点信道只接受加密帧`），口令解不开是 `401`，同一来源连续 3 次认证失败锁 60 秒返回 `429`；
- 11 号文档原有的 `/v1/*` 明文端点行为不变（脚本/AI 用），但**开启局域网时界面必须提示**：给脚本用可以，跨机联合请用节点配对；
- 口令强度：少于 12 位或纯字典词 → 允许配对但红字提示"信道加密强度取决于口令"。推荐用「生成」出的 64 位十六进制口令。

### 2.3 端点（`/v1/node/*`，全部加密）
除 `hello` 外全部是 `POST`，请求体与响应体都是加密帧（`{iv, ct, seq}`），路径同时绑进 AAD：

| 端点 | 语义 | 幂等 |
|---|---|---|
| `GET /v1/node/hello` | 明文握手：`{deviceId, salt, protocol, version, platform}`（不含指纹） | 是 |
| `POST /v1/node/state` | 加密探活：`{deviceId, version, platform, protocol, busy, projects:[{id,name,hash,apis}]}` | 是 |
| `POST /v1/node/tree` | 某远端项目的可跑结构：`{collections:[{id,name,apis}], envs:[{id,name}]}`，代为测试前先取它 | 是 |
| `POST /v1/node/pull` | 导出指定项目为 `.tapi`（**强制 strip 密钥**）回传 `{content, apis, collections}` | 是 |
| `POST /v1/node/push` | 接收 `.tapi` 文本并按 `mode` / `apiConflict` 导入（事务，失败回滚） | 否 |
| `POST /v1/node/run` | 代为执行：`{scopeType, scopeId, envId, opId}` → 返回 `{runId, total}` | 是（同 `opId` 返回同一 `runId`） |
| `POST /v1/node/run-get` | 取运行结果：`{runId}` → 逐项 + 汇总 + `finished` | 是 |
| `POST /v1/node/run-cancel` | 取消本机代为发起的运行：`{runId}` | 是 |

版本不兼容（`protocol` 与本机 `NODE_PROTOCOL` 不等）→ 配对当场拒绝并提示升级，不静默降级。
`format_version` 高于本机支持范围时，由 `.tapi` 导入闸门拒绝（08 号文档 §5）。

## 3. 项目互传（用户口径的"同步"）

- **拉取**：选远端项目 → 预览（集合/接口/环境计数、被剔除的密钥数、与本地同名项目的差异）→ 选择策略：
  新建 / 合并进同名项目 / 覆盖同名项目内容；接口判重复用 08 号文档 §5 的 skip/overwrite/duplicate。
- **推送**：本地项目 → 选远端 → 同一套预览与策略，远端按 `.tapi` 导入流程执行（事务、失败回滚）。
- **密钥**：任何方向都只传 `secret` 变量名与 `redacted:true` 占位，值永不跨机；导入侧红字提示"需本机补填 N 项"。
- **不自动同步**：没有后台常驻比对；面板给"上次同步时间 + 本地/远端项目 hash 是否一致"，不一致时提示可拉可推。
- 项目 `hash` = 对该项目内 `集合id:更新时间` 与 `接口id:更新时间` 排序拼接后的 sha256 前 12 位（`electron/node/service.ts` 的 `projectHash`），
  只用于"看起来是否一致"的提示，不作为冲突判定依据；导入侧的重复判定仍走 08 号文档 §5 的语义比对。

## 4. 代为测试（指定某台机器跑）

1. 选目标节点 + 远端项目里的集合/接口 + 远端环境（**必须显式选，不跟随本机激活环境**）。
2. 发起前 GUI 确认条：目标机器、范围、接口数、预计请求量、会打到的 host 清单（越界 host 直接拒绝）。
3. 执行：`POST /v1/node/run` → 轮询 `GET /v1/node/run/{id}`（1s 起指数退避，上限 5s）→ 结果落地为本地 `runner_run`，
   `scope_type='remote'`、`scope_name='<节点名> · <集合名>'`，逐项与断言完整保留，历史仍留在远端机器（只回传摘要与失败项详情）。
4. 完成汇报走 15 号文档：`node.finished` 事件，标题 `<节点名>：<通过>/<总数> 通过`，失败升 `warn`。

## 5. 多机联合测试

- **切片**：默认按接口数均匀切片（`ceil(N/nodes)`），可切"按集合目录"或手工指定；同一接口只落一个节点，避免重复打靶。
- **一致性前置**：所有参与节点必须报同一个项目 `hash`，不一致时默认**先同步再跑**（弹窗给"跳过该节点/先互传/强行执行"三选）。
- **执行**：并行下发 `run`（各节点独立 `opId`），任一节点失败不影响其他；全部结束后本地汇总成**一份**联合运行记录：
  `scope_type='joint'`，逐项带 `node` 标注，通过率按接口数加权（不是按节点数平均）。
- **限流**：全局并发节点数上限 8；单节点同一时刻只允许一个联合任务（`busy` 时按 `skip` 处理并提示）。
- **取消**：本地一键取消会向所有参与节点广播 `cancel`。
- **离线降级**：节点掉线 → 该片标 `skipped` 并在通知里点名，其余照常；不重试到超时以外的时间（默认单节点等待 90s）。

## 6. 多机联合压力测试（依赖单机压测引擎，未实现）

13 号文档 §1 的单机压测引擎尚未落地，联合压测**只能在其之后**开工；本节点先定死接口与聚合口径，避免将来各写一套：

- 分片：按 VU 数切（`vus_total / nodes`，余数给前 k 台），可选按数据文件行切片（每台吃不同数据行，禁止重叠）。
- 时钟：协调者下发统一 `startAt`（绝对毫秒），节点各自对齐；偏差 > 250ms 的节点被剔除并提示。
- 聚合：**分位数不能平均**。各节点每 1s 上报 `{count, errors, histogram}`（固定桶），协调者按桶相加后再算 p50/p90/p95/p99；
  RPS 取总完成数除以有效时间窗（以最晚结束的节点为界）。
- 阈值判定与安全：沿用 13 号文档 §1.5 的熔断与外网限额闸门，**预算按节点数放大前必须用户确认**；
  联合压测目标 host 必须在项目环境声明清单内，且默认只允许 RFC1918 地址段，打公网需逐次确认。
- 结果：本地一份 `load_run`（含每节点贡献与剔除原因），报告导出格式与单机一致。

## 7. UI 落点（遵循 06 号文档，禁 emoji、全 SVG）

已实现（右侧面板第四档「节点」，与 响应 / Runner / 任务 并列）：

- **本机视图条**（`node-self`）：状态点 + "本机可被配对 / 暂不可被配对" + `IP:端口`（仅本机时写 loopback）+ 设备号尾 6 位 + 本机指纹；未就绪时给指向「设置 → 开放调用」的提示。
- **节点行**：状态点（SVG，绿=就绪 / 灰=停用 / 橙=忙 / 红=不可达 / 浅灰=未探活）+ 别名 + `IP:端口` + 版本 + 项目数 + 平台 + 上次探活时间 + 指纹行（`已确认` 绿药丸 / `未确认，不能推送或代跑` 橙药丸）+ 最近一次事件文本；行内操作：探活、拉取、推送、代为运行、编辑、解除配对。未确认指纹时推送与代跑按钮禁用；行内操作常驻可见（`.row-actions` 的 hover 显隐只对项目树生效）。
- **配对对话框**：`IP` + 端口两格（默认 4730）、口令（`type=password` 掩码，编辑时留空表示不改）、别名、标签；口令短于 12 位当场红字提示信道强度；本机还不可配对时同步提示对方回连会失败。
- **拉取向导**：远端项目下拉（名称 + 接口数 + hash 前 6 位）→ `.tapi-summary` 摘要（远端规模、同名本机项目与接口数、"密钥只传变量名"）→ 落地方式（新建 / 合并进 + 目标项目）→ 同名接口策略 → 拉取。
- **推送向导**：本机项目下拉（含递归接口数）+ 同名接口策略 + 对端同名项目提示 + 推送。
- **代为测试向导**：远端项目 → 运行范围（整个项目或某集合，接口数即时显示）→ **远端环境必须显式选**，未选时「开始运行」禁用；正文说明将打到哪台机器、结果会落地为本机运行记录并汇报。
- **解除配对**：二次确认，文案点明"只删除本机保存的信道密钥与指纹锁定，不影响对方机器上的任何数据"。

未实现：联合测试向导（选参与节点 → 切片预览 → 一致性告警 → 每节点进度 → 汇总报告）。

## 9. 安全红线（并入 20 号文档 §8 清单）

- 口令与设备密钥派生值不落明文；`node` 表只存 scrypt 派生值。
- 跨机流量必须加密；未加密的 `/v1/node/*` 请求一律拒绝。
- 密钥变量值、历史记录、Cookie 永不跨机；`.tapi` 互传强制 strip。
- 任何写操作（push / run / run-cancel，以及将来的 joint-start）都要求该节点指纹已确认；被调用一方沿用**自己**的项目环境 host 声明闸门执行代跑（11 号文档 §1.3），发起方不替对方放宽。
- 每次节点调用写 `node_call_log`（入站与出站都记），摘要脱敏；同一来源连续 3 次认证失败锁该来源地址 60 秒并返回 `429 RATE_LIMIT`，锁定与失败以 `LOCKED` / `UNAUTHORIZED` 记录留痕。通知中心的认证失败告警尚未接（只在审计里可见）。
- 联合压测默认只允许 RFC1918 目标；打公网逐次确认（13 号文档 §1.5 同源规则）。
