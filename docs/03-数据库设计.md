# ToAPI — SQLite 数据库设计

## 1. 设计原则

- 单文件 `toapi.db`，WAL 模式，外键开启。
- 所有表带 `created_at` / `updated_at`（Unix 毫秒）。
- 删除策略：项目/集合级联删除接口；接口删除保留历史（历史只读快照）。
- 排序不用自增 ID 依赖，统一 `sort_order` 实数列（拖拽插入取中值）。
- 所有 JSON 字段存 TEXT，读写由 Repo 层序列化，禁止散落 `JSON.parse`。

## 2. ER 概览

```
project ─┬─ collection ─┬─ api
         │              └─ collection（自引用，支持嵌套）
         └─ environment ── variable
variable（global 级，project_id 为 NULL）
api ── request_snapshot ── history ── test_result
runner_run ── runner_item
```

## 3. 表结构

### 3.1 project — 项目
| 列 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | ULID |
| name | TEXT NOT NULL | 项目名 |
| description | TEXT DEFAULT '' | |
| settings | TEXT DEFAULT '{}' | 项目级默认伪装等 |
| auth | TEXT DEFAULT '{"type":"none"}' | 根集合认证（Postman 兼容，v3 迁移） |
| variables | TEXT DEFAULT '[]' | 根集合变量 `[{key,value,enabled,secret,desc}]`（v3） |
| pre_script / post_script | TEXT DEFAULT '' | 根集合级脚本，执行顺序见 05 号文档 §1（v3） |
| source_json | TEXT DEFAULT '{}' | Postman 原文留存，导出回填（v3） |
| sort_order | REAL NOT NULL | 拖拽排序 |
| created_at / updated_at | INTEGER | |

### 3.2 collection — 集合（可嵌套）
| 列 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | |
| project_id | TEXT NOT NULL REFERENCES project(id) ON DELETE CASCADE | |
| parent_id | TEXT NULL REFERENCES collection(id) ON DELETE CASCADE | NULL = 根集合 |
| name | TEXT NOT NULL | |
| description | TEXT DEFAULT '' | 文件夹描述（v3） |
| pre_script / post_script | TEXT DEFAULT '' | 集合级脚本（对集合内所有请求生效） |
| auth | TEXT DEFAULT '{"type":"inherit"}' | 集合认证，沿父链继承（v3） |
| variables | TEXT DEFAULT '[]' | 集合变量（v3） |
| source_json | TEXT DEFAULT '{}' | Postman 原文留存（v3） |
| sort_order | REAL NOT NULL | |

### 3.3 api — 接口
| 列 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | |
| collection_id | TEXT NOT NULL REFERENCES collection(id) ON DELETE CASCADE | |
| name | TEXT NOT NULL | |
| description | TEXT DEFAULT '' | 请求描述（v3） |
| method | TEXT NOT NULL | GET/POST/PUT/DELETE/PATCH/HEAD/OPTIONS |
| url | TEXT NOT NULL | 可含 `{{var}}` |
| params | TEXT DEFAULT '[]' | `[{key,value,enabled,desc}]` |
| headers | TEXT DEFAULT '[]' | 同上 |
| body_type | TEXT DEFAULT 'none' | none/json/form/urlencoded/raw/binary；B3 增加 graphql |
| body | TEXT DEFAULT '' | |
| auth | TEXT DEFAULT '{}' | `{type:'none'\|'inherit'\|'bearer'\|'basic'\|'apikey', ...}`，`inherit` 沿集合链向上（v3） |
| fake | TEXT DEFAULT '{}' | 伪装配置，见 §3.8 |
| pre_script / post_script | TEXT DEFAULT '' | 接口级脚本 |
| extractors | TEXT DEFAULT '[]' | `[{name, source:'body\|'header\|'status', type:'jsonpath\|'regex', expr, scope:'runtime\|'env\|'global'}]` |
| source_json | TEXT DEFAULT '{}' | Postman 原文留存（v3） |
| sort_order | REAL NOT NULL | |

### 3.4 environment — 环境
| 列 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | |
| project_id | TEXT NOT NULL REFERENCES project(id) ON DELETE CASCADE | |
| name | TEXT NOT NULL | 如 dev / staging / prod |
| is_active | INTEGER DEFAULT 0 | 每个项目同时最多 1 个激活（应用层保证） |
| source_json | TEXT DEFAULT '{}' | Postman Environment 元数据留存（v3） |

### 3.5 variable — 变量
| 列 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | |
| scope | TEXT NOT NULL | 'global' / 'environment' |
| environment_id | TEXT NULL REFERENCES environment(id) ON DELETE CASCADE | scope=environment 时必填 |
| key | TEXT NOT NULL | |
| value | TEXT DEFAULT '' | |
| secret | INTEGER DEFAULT 0 | 1 时 UI 掩码、导出可选剔除 |
| enabled | INTEGER DEFAULT 1 | 0 时不参与插值（Postman 禁用变量，v3） |
| UNIQUE(scope, environment_id, key) | | |

> 运行时变量（链式请求中提取的）不落库，只存内存，Runner 结束即弃。

### 3.6 history — 请求历史（快照）
| 列 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | |
| api_id | TEXT NULL REFERENCES api(id) ON DELETE SET NULL | 接口删除后历史保留 |
| project_id | TEXT NOT NULL | 冗余，便于按项目清理 |
| request_snapshot | TEXT NOT NULL | 发送时的完整最终请求（插值与脚本执行后） |
| response | TEXT NOT NULL | `{status, headers, bodyRef, timeMs, size}` |
| body_path | TEXT NULL | 大 body（>256KB）落文件，DB 存路径 |
| created_at | INTEGER | |
索引：`(project_id, created_at DESC)`、`(api_id, created_at DESC)`

### 3.7 runner_run / runner_item — 批量执行记录
- `runner_run(id, scope_type, scope_id, started_at, finished_at, total, passed, failed, skipped, iteration_count, report_json)`
  - `scope_type`：`'collection'` / `'api'` / `'project'` / `'case'`（案例单跑也入此表，见 09 号文档）
  - `total` = 范围内接口数 × 迭代数（计划值，`setNextRequest` 截断后实际条目可少）
  - `iteration_count`：本次运行的迭代轮数，无数据文件时为 1（23 号文档 §5.2）
- `runner_item(id, run_id REFERENCES runner_run ON DELETE CASCADE, api_id, api_name, status, time_ms, assertions_json, logs_json, error, sort_order, iteration)`
  - 排序索引 `(run_id, iteration, sort_order)`：同一轮内按 `sort_order`，跨轮按 `iteration`

### 3.7b case — 多语言案例
| 列 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | ULID |
| collection_id | TEXT NOT NULL REFERENCES collection(id) ON DELETE CASCADE | 与接口同级挂在集合下 |
| name | TEXT NOT NULL | |
| lang | TEXT NOT NULL | `'js'` / `'python'` |
| code | TEXT NOT NULL | 案例源码 |
| bound_api_id | TEXT NULL REFERENCES api(id) ON DELETE SET NULL | 由哪个接口生成 |
| env_lock | TEXT NULL | 锁定运行环境 id（跨部门交付用） |
| sort_order | REAL NOT NULL | |
| created_at / updated_at | INTEGER | |

### 3.7c md_document — MD 测试文档绑定（详见 10 号文档）
| 列 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | ULID |
| project_id | TEXT NOT NULL REFERENCES project(id) ON DELETE CASCADE | |
| file_path | TEXT NOT NULL UNIQUE | `.tapi.md` 绝对路径 |
| content_hash | TEXT NOT NULL | sha256，检测外部修改 |
| sync_state | TEXT NOT NULL DEFAULT 'synced' | `'synced'/'file-changed'/'app-changed'/'conflict'` |
| last_synced_at | INTEGER | |

### 3.7d app_settings / external_call_log — 开放通道（详见 11 号文档）
- `app_settings(key TEXT PK, value TEXT)`：开放通道开关、端口、token 哈希（不存明文）、已授权 MCP 客户端清单。
- `external_call_log(id, channel TEXT, tool TEXT, client TEXT, params_summary TEXT, ok INTEGER, error_code TEXT, time_ms REAL, created_at INTEGER)`
  - `channel`：`'http' / 'mcp'`；`params_summary` 为脱敏摘要（secret 值永不落入）；保留最近 5000 条环形清理。
  - 索引：`(created_at DESC)`、`(channel, created_at DESC)`。

### 3.7e schedule_task / action_macro — 定时与宏（详见 12 号文档）
- `schedule_task(id, name, enabled, target_type, target_id, schedule_json, env_id, overlap_policy, misfire_policy, notify_json, last_run_at, last_run_id, next_run_at, created_at, updated_at)`
- `action_macro(id, name, steps_json, created_at, updated_at)`，索引 `schedule_task(enabled, next_run_at)`

### 3.7f load_run / load_run_bucket — 压测（详见 13 号文档）
- `load_run(id, profile_json, started_at, finished_at, vus, total, error_count, p50, p90, p95, p99, rps_avg, verdict, report_path)`
- `load_run_bucket(id, run_id REFERENCES load_run ON DELETE CASCADE, bucket_ts, count, errors, p50, p95, p99, rps)`
- 不存逐请求明细；错误抽样快照入 history（`is_load_sample=1`，history 表加该列，默认 0）。

### 3.7g notification — 通知中心（详见 15 号文档）
- `notification(id, type, level, title, body, source_type, source_id, read INTEGER DEFAULT 0, created_at)`
- 索引 `(read, created_at DESC)`；保留最近 1000 条环形清理。
- 订阅规则（事件类型 × 通道矩阵）存 `app_settings` 的 `notify_rules` 键。

### 3.7h ai_call_log — AI 调用审计（详见 16 号文档）
- `ai_call_log(id, feature, model, prompt_tokens, completion_tokens, adopted INTEGER DEFAULT 0, time_ms, created_at)`，保留最近 2000 条。
- Provider 配置存 `app_settings.ai_provider`；`api_key` 走全局 secret 变量（`ai.api_key`），不落此表。

### 3.8 伪装配置（api.fake JSON Schema）
```json
{
  "ua": "string 或 @preset:chrome-win",
  "headers": [{"key": "...", "value": "..."}],
  "proxy": {"enabled": false, "url": "http://127.0.0.1:7890"},
  "followRedirects": true,
  "maxRedirects": 5,
  "timeoutMs": 30000,
  "cookieJar": "inherit" ,
  "ignoreTlsErrors": false
}
```
项目级默认伪装存在 project.settings（新增 `settings TEXT DEFAULT '{}'` 列），接口级覆盖项目级。

## 4. 迁移机制

- `PRAGMA user_version` 记录版本，`electron/db/migrations/` 下迁移以 TS 常量内嵌（`001_init`、`002_runner`、`003_postman`…），打包后不依赖外部 `.sql` 文件。
- 已登记迁移：
  - `001_init`：项目 / 集合 / 接口 / 环境 / 变量 / 历史 / 设置
  - `002_runner`：`runner_run` / `runner_item`
  - `003_postman`：project/collection 的 `auth`、`variables`、`description`、`source_json`（project 另有 `pre_script`/`post_script`）；api 的 `description`、`source_json`；environment 的 `source_json`；variable 的 `enabled`（23 号文档 §3.1）
  - `004_runner_iteration`：`runner_run.iteration_count`、`runner_item.iteration`，并把 `runner_item_run_idx` 重建为 `(run_id, iteration, sort_order)`（23 号文档 §5.2）
- 每次迁移包事务，失败整体回滚并弹错引导导出数据。
- 启动时自动备份：迁移前复制 `toapi.db` → `backups/toapi.v{n}.db`（保留最近 5 份）。

## 5. 索引与体量假设

- 除上述索引外：`variable(scope, environment_id)`、`api(collection_id, sort_order)`。
- 设计体量：单用户、百级项目、万级接口、十万级历史。历史提供按项目/按天数的清理入口。
- 大响应体策略：>256KB 写 `userData/bodies/{historyId}.bin`，DB 只存路径与摘要，查询列表不加载 body。
