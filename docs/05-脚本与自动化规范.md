# ToAPI — 脚本与自动化规范

> 脚本引擎是 ToAPI 的核心差异化能力：请求前改参数、请求后做断言、
> 脚本内发联合请求、一键伪装。JS 脚本运行在 `worker_threads` + `node:vm` 沙箱中；
> **Python 案例**经子进程桥接走同一管道，API 对齐关系见 09 号文档 §3。
> 自 v0.2.0 起同时提供 `pm.*` 兼容层（23 号文档 §4），Postman 脚本可源码级运行。

## 1. 脚本挂载点（执行顺序）

```
项目 pre_script（根集合）
  → 集合 pre_script（从外层到内层依次执行）
    → 接口 pre_script
      → 发送请求
    → 接口 post_script
  → 集合 post_script（从内层到外层）
→ 项目 post_script
```

| 挂载点 | 典型用途 |
|---|---|
| Pre-request | 生成签名/时间戳/Token、动态改 Header/Body、条件跳过 |
| Post-response | 提取变量（也可脚本化）、写环境变量 |
| Test（写在 post 中，`toapi.test`） | 断言状态码、字段、耗时 |

同一请求的多个前置脚本依次执行，前一个脚本对 `toapi.request` 的修改会传给下一个；
后置脚本按接口 → 内层集合 → 外层集合 → 项目顺序聚合断言，任一失败本轮失败。
集合级脚本与项目级脚本同样能访问当前请求/响应上下文（23 号文档 §4.1）。

## 2. 沙箱内置对象 `toapi`

```ts
// ── 请求上下文（pre 中可写，post 中只读） ──
toapi.request.method: string
toapi.request.url: string
toapi.request.headers: Record<string, string>
toapi.request.body: string
toapi.request.setHeader(k, v): void
toapi.request.setBody(s): void
toapi.request.skip(reason?): void          // 中止本次发送，标记 SKIPPED

// ── 响应上下文（仅 post 可用） ──
toapi.response.status: number
toapi.response.headers: Record<string, string>
toapi.response.body: string
toapi.response.json(): any                // 解析失败抛 SCRIPT_ERROR
toapi.response.timeMs: number

// ── 变量 ──
toapi.vars.get(key): string | undefined   // 运行时 → 环境 → 集合链内到外 → 项目根 → 全局
toapi.vars.set(key, value): void          // 写运行时变量（本次 Runner 内有效）
toapi.env.set(key, value): Promise<void>  // 写当前环境（持久化），无激活环境时 reject
toapi.globals.set(key, value): Promise<void>

// ── 联合请求（链式） ──
const res = await toapi.request.send({
  method: 'POST',
  url: '{{baseUrl}}/login',
  headers: {...},
  body: JSON.stringify({...}),
  fake: { ua: '@preset:chrome-win' }      // 可选，单请求级伪装
})
// res 结构同 toapi.response
// 子请求复用当前代理/CookieJar/超时管道，写入历史（标记 isSubRequest）

// ── 伪装 ──
toapi.fake.ua('@preset:chrome-win')       // 设置 UA，可传任意字符串
toapi.fake.header('Referer', 'https://example.com')
toapi.fake.proxy('http://127.0.0.1:7890') // 仅本次请求生效
toapi.fake.timeout(10000)
toapi.fake.noRedirects()

// ── 断言 ──
toapi.test('状态码为 200', () => {
  toapi.expect(toapi.response.status).toBe(200)
})
toapi.expect(value).toBe / .toContain / .toMatch(regex) / .toBeLessThan / .toBeDefined / ...
// toapi.expect 与 pm.expect 共用同一 chai 子集，支持 .not / .deep 与链式 .and
// toapi.test 的回调必须是同步的：异步判断先在脚本主体 await 完，再调 toapi.test
// 需要异步/回调式断言时用 pm.test（§2.1）
// 前置脚本里的 toapi.test 同样计入本轮断言结果

// ── 工具 ──
toapi.log(...) / toapi.warn(...) / toapi.error(...)
toapi.sleep(ms)                           // 上限 30s
toapi.uuid() / toapi.timestamp() / toapi.randomInt(min, max)
toapi.base64Encode(s) / toapi.base64Decode(s)
toapi.md5(s) / toapi.sha256(s) / toapi.hmacSha256(key, s)
// 不提供：文件系统、child_process、原生网络模块
```

### 2.1 `pm.*` 兼容层

同一沙箱内同时注入 Postman 的 `pm` 对象，映射关系：

| Postman | ToAPI 等价 | 说明 |
|---|---|---|
| `pm.test` / `pm.expect` | `toapi.test` / `toapi.expect` | 断言结果进入同一份 `AssertionResult` |
| `pm.request` | `toapi.request` | 前置可写、后置只读 |
| `pm.response` | `toapi.response` | `json()` / `text()` / `code` / headers |
| `pm.variables` | 请求级 local 变量 | 优先级最高，不跨请求 |
| `pm.collectionVariables` | 集合变量 | 持久化，Runner 内可写 |
| `pm.environment` / `pm.globals` | 环境 / 全局变量 | 与 `toapi.env` / `toapi.globals` 同源 |
| `pm.sendRequest` | `toapi.request.send` | 复用代理、CookieJar、历史与子请求限额 |
| `pm.cookies` | CookieJar | 项目级共享，`get/set/has/unset/toObject` |

- `pm.test` 同时支持同步、返回 Promise 与 `done` 回调三种写法；异步用例在脚本收尾前统一收敛，再汇总断言。`pm.test.skip` 记为 `skipped`，不判失败，响应页与 Runner 以 dash 图标展示。
- `pm.response.to.have.status/header/body/jsonBody` 与 `pm.response.to.be.*` 状态标志可用；`pm.response.cookies` 解析本次响应的 `Set-Cookie`。
- 后置脚本对 `pm.request` 只读，写入尝试记 warning 但不推翻响应。
- 变量写入：`pm.variables` → 请求级 local（不跨请求），`pm.collectionVariables` → 集合定义（Runner/单发均回写），`pm.environment` / `pm.globals` → 持久化；无激活环境时写环境变量产生失败断言而非中断脚本。

完整覆盖表、执行顺序与沙箱库见 23 号文档 §4；`pm.*` 与 `toapi.*` 双轨并存，同名变量不要混用。

### 2.2 动态变量与沙箱库

- **动态变量**：URL / Header / Body / auth 字段中的 `{{$...}}` 在发送前求值，同一次发送内每个占位符**独立取值**（需要同值复用先写入变量）；未知 `{{$name}}` 保留原文并进入未解析变量清单。完整键名清单见 23 号文档 §4.5，由 `electron/postman/dynamic-vars.ts` 维护并由单测锁定。
- **注入库**：`_`（lodash）、`CryptoJS`、`uuid.v4/v7`、`moment`、`atob/btoa`、`URL/URLSearchParams`、`TextEncoder/TextDecoder`；定时器 `setTimeout/clearTimeout/setInterval/clearInterval` 可用（受脚本 5s 总时限约束）；`console.*` 转发到脚本日志面板。
- 仍然不可用：`fetch`、`XMLHttpRequest`、`require`、`process` 与任何文件系统/进程 API；网络只能走 `pm.sendRequest` / `toapi.request.send`。

## 3. UA 预设库（`@preset:*`）

| 预设 | 值（节选） |
|---|---|
| `@preset:chrome-win` | 当前主流 Chrome on Windows UA |
| `@preset:chrome-mac` | Chrome on macOS |
| `@preset:firefox-win` | Firefox on Windows |
| `@preset:safari-ios` | Mobile Safari |
| `@preset:edge-win` | Edge |
| `@preset:postman` | PostmanRuntime UA（伪装为 Postman 流量） |
| `@preset:curl` | curl/x.xx |
| `@preset:okhttp` | okhttp/4.x（伪装为安卓 App 流量） |

预设表随应用更新维护，存于 `electron/http/ua-presets.json`，UI 伪装面板与脚本共用。

## 4. 变量提取器（非脚本方式，声明式）

接口上可配置提取器，响应返回后自动执行，顺序在 post_script 之前：

```json
{
  "name": "token",
  "source": "body",
  "type": "jsonpath",
  "expr": "$.data.access_token",
  "scope": "runtime"
}
```

| 字段 | 取值 |
|---|---|
| source | `body` / `header` / `status` |
| type | `jsonpath` / `regex`（regex 取第一个捕获组） |
| scope | `runtime`（链式传递）/ `env` / `global` |

**规则**：提取器优先于脚本（声明式更简单）；脚本与提取器同名时脚本后执行覆盖。

## 5. 联合请求（链式）两种模式

### 模式 A：脚本式（灵活）
在 pre_script 中 `await toapi.request.send({...})` 登录取 token，再 `toapi.request.setHeader('Authorization', ...)`。适合逻辑复杂、条件分支多的场景。

### 模式 B：流程式（可视化 Runner）
集合 Runner 按 `sort_order` 串行执行接口，上游接口的提取器把值写入运行时变量，下游接口 URL/Header 用 `{{token}}` 引用。

| 选项 | 默认 | 说明 |
|---|---|---|
| stopOnFail | false | 断言失败是否中止后续（CLI `--bail`） |
| delayMs | 0 | 请求间隔（CLI `--delay`） |
| iterationData | 无 | 数据行数组，每行一次迭代；行值参与插值时高于环境变量、低于 local（23 号文档 §5.1） |
| iterationCount | 数据行数（无数据文件时 1） | 行数不足时循环取行（CLI `--iteration-count`） |
| timeoutMs | 接口自身设置 | 覆盖本轮所有请求的超时（CLI `--timeout`） |

提取器无命中在 Runner/CLI 上下文里记为失败断言（`提取器 <名称>: 未命中`），是否中止后续由 `stopOnFail` 决定；单次发送只标注未命中，不影响判定。
`pm.execution.setNextRequest(名称)` 在同轮迭代内按名称跳转（未知名与 `null` 都结束本轮），只有 Runner/CLI 上下文生效；跳转次数超过 `接口数 × 20 + 20` 时终止本轮并记 `error`，防止脚本自跳造成死循环。

## 6. 沙箱安全与熔断

| 限制 | 默认值 | 说明 |
|---|---|---|
| 单脚本时限 | 5s | 同步阶段由 `vm.runInContext({timeout})` 拦；异步阶段（await 后的死循环/悬挂 Promise）由宿主 `worker.terminate()` 强杀，返回 `SCRIPT_TIMEOUT`，请求中止 |
| 内存上限 | 128MB | worker `resourceLimits.maxOldGenerationSizeMb` |
| 子请求深度 | 8 层 | 防递归爆炸（A 发 B 发 A…），超限时子请求抛错 |
| 子请求总数 | 50 次/主请求 | 同上 |
| 禁全局 | `fetch`/`XMLHttpRequest`/`process`/`require` 不存在 | 沙箱是独立 worker 线程内的 vm 上下文，用户代码拿不到任何宿主对象；网络只能走 `toapi.request.send` / `pm.sendRequest` |

**实现形态（2026-10-24）**：每次脚本执行起一个专用 worker 线程，线程内用 `node:vm` 创建注入 `toapi`、`pm` 与 §2.2 白名单库的上下文；脚本以 async IIFE 编译执行，`pm.sendRequest` / `toapi.request.send` / `toapi.env.set` / `pm.environment.set` 等通过消息回宿主，由宿主的 HttpEngine 与 Repo 落地，因此脚本内的子请求与手动请求共享同一套伪装、代理、CookieJar 与历史入库路径。worker 结束即销毁，运行时变量与 local 变量通过 `done` 消息回传宿主，供链式后续接口插值。

脚本编辑器的静态检查：检测到 `fetch(`、`require(` 等直接画红线提示"沙箱中不可用，请使用 toapi.request.send"。

## 7. 示例：登录 → 带 Token 查询

```js
// 接口「查询订单」的 pre_script
const login = await toapi.request.send({
  method: 'POST',
  url: toapi.vars.get('baseUrl') + '/api/login',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    username: toapi.vars.get('username'),
    sign: toapi.md5(toapi.vars.get('password') + toapi.timestamp())
  }),
  fake: { ua: '@preset:okhttp' }
})

toapi.test('登录成功', () => toapi.expect(login.status).toBe(200))
const token = login.json().data.token
toapi.vars.set('token', token)
toapi.request.setHeader('Authorization', 'Bearer ' + token)
```
