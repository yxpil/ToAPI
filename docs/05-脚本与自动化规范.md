# ToAPI — 脚本与自动化规范

> 脚本引擎是 ToAPI 的核心差异化能力：请求前改参数、请求后做断言、
> 脚本内发联合请求、一键伪装。JS 脚本运行在 isolated-vm 沙箱中；
> **Python 案例**经子进程桥接走同一管道，API 对齐关系见 09 号文档 §3。

## 1. 脚本挂载点（执行顺序）

```
集合 pre_script（从外层到内层依次执行）
  → 接口 pre_script
    → 发送请求
  → 接口 post_script
→ 集合 post_script（从内层到外层）
```

| 挂载点 | 典型用途 |
|---|---|
| Pre-request | 生成签名/时间戳/Token、动态改 Header/Body、条件跳过 |
| Post-response | 提取变量（也可脚本化）、写环境变量 |
| Test（写在 post 中，`toapi.test`） | 断言状态码、字段、耗时 |

## 2. 沙箱内置对象 `toapi`

```ts
// ── 请求上下文（pre 中可写，post 中只读） ──
toapi.request.method: string
toapi.request.url: string
toapi.request.headers: Record<string, string>
toapi.request.body: string
toapi.request.setHeader(k, v): void
toapi.request.setBody(s): void
toapi.request.skip(reason?): void          // 中止本次发送，标记 SKIPPED

// ── 响应上下文（仅 post 可用） ──
toapi.response.status: number
toapi.response.headers: Record<string, string>
toapi.response.body: string
toapi.response.json(): any                // 解析失败抛 SCRIPT_ERROR
toapi.response.timeMs: number

// ── 变量 ──
toapi.vars.get(key): string | undefined   // 查找顺序：运行时 → 环境 → 全局
toapi.vars.set(key, value): void          // 写运行时变量（本次 Runner 内有效）
toapi.env.set(key, value): void           // 写当前环境（持久化）
toapi.globals.set(key, value): void

// ── 联合请求（链式） ──
const res = await toapi.request.send({
  method: 'POST',
  url: '{{baseUrl}}/login',
  headers: {...},
  body: JSON.stringify({...}),
  fake: { ua: '@preset:chrome-win' }      // 可选，单请求级伪装
})
// res 结构同 toapi.response
// 子请求复用当前代理/CookieJar/超时管道，写入历史（标记 isSubRequest）

// ── 伪装 ──
toapi.fake.ua('@preset:chrome-win')       // 设置 UA，可传任意字符串
toapi.fake.header('Referer', 'https://example.com')
toapi.fake.proxy('http://127.0.0.1:7890') // 仅本次请求生效
toapi.fake.timeout(10000)
toapi.fake.noRedirects()

// ── 断言 ──
toapi.test('状态码为 200', () => {
  toapi.expect(toapi.response.status).toBe(200)
})
toapi.expect(value).toBe / .toContain / .toMatch(regex) / .toBeLessThan / .toBeDefined / ...
// toapi.test 的回调必须是同步的：异步判断先在脚本主体 await 完，再调 toapi.test
// 前置脚本里的 toapi.test 同样计入本轮断言结果

// ── 工具 ──
toapi.log(...) / toapi.warn(...) / toapi.error(...)
toapi.sleep(ms)                           // 上限 30s
toapi.uuid() / toapi.timestamp() / toapi.randomInt(min, max)
toapi.base64Encode(s) / toapi.base64Decode(s)
toapi.md5(s) / toapi.sha256(s) / toapi.hmacSha256(key, s)
// 不提供：文件系统、child_process、原生网络模块
```

## 3. UA 预设库（`@preset:*`）

| 预设 | 值（节选） |
|---|---|
| `@preset:chrome-win` | 当前主流 Chrome on Windows UA |
| `@preset:chrome-mac` | Chrome on macOS |
| `@preset:firefox-win` | Firefox on Windows |
| `@preset:safari-ios` | Mobile Safari |
| `@preset:edge-win` | Edge |
| `@preset:postman` | PostmanRuntime UA（伪装为 Postman 流量） |
| `@preset:curl` | curl/x.xx |
| `@preset:okhttp` | okhttp/4.x（伪装为安卓 App 流量） |

预设表随应用更新维护，存于 `electron/http/ua-presets.json`，UI 伪装面板与脚本共用。

## 4. 变量提取器（非脚本方式，声明式）

接口上可配置提取器，响应返回后自动执行，顺序在 post_script 之前：

```json
{
  "name": "token",
  "source": "body",
  "type": "jsonpath",
  "expr": "$.data.access_token",
  "scope": "runtime"
}
```

| 字段 | 取值 |
|---|---|
| source | `body` / `header` / `status` |
| type | `jsonpath` / `regex`（regex 取第一个捕获组） |
| scope | `runtime`（链式传递）/ `env` / `global` |

**规则**：提取器优先于脚本（声明式更简单）；脚本与提取器同名时脚本后执行覆盖。

## 5. 联合请求（链式）两种模式

### 模式 A：脚本式（灵活）
在 pre_script 中 `await toapi.request.send({...})` 登录取 token，再 `toapi.request.setHeader('Authorization', ...)`。适合逻辑复杂、条件分支多的场景。

### 模式 B：流程式（可视化 Runner）
集合 Runner 按 `sort_order` 串行执行接口，上游接口的提取器把值写入运行时变量，下游接口 URL/Header 用 `{{token}}` 引用。

| 选项 | 默认 | 说明 |
|---|---|---|
| stopOnFail | false | 断言失败是否中止后续 |
| delayMs | 0 | 请求间隔 |
| stopOnExtractFail | true | 提取器无命中时中止（防级联脏数据） |

## 6. 沙箱安全与熔断

| 限制 | 默认值 | 说明 |
|---|---|---|
| 单脚本时限 | 5s | 同步阶段由 `vm.runInContext({timeout})` 拦；异步阶段（await 后的死循环/悬挂 Promise）由宿主 `worker.terminate()` 强杀，返回 `SCRIPT_TIMEOUT`，请求中止 |
| 内存上限 | 128MB | worker `resourceLimits.maxOldGenerationSizeMb` |
| 子请求深度 | 8 层 | 防递归爆炸（A 发 B 发 A…），超限时子请求抛错 |
| 子请求总数 | 50 次/主请求 | 同上 |
| 禁全局 | `fetch`/`XMLHttpRequest`/`process`/`require` 不存在 | 沙箱是独立 worker 线程内的 vm 上下文，用户代码拿不到任何宿主对象；网络只能走 `toapi.request.send` |

**实现形态（2026-10-24）**：每次脚本执行起一个专用 worker 线程，线程内用 `node:vm` 创建只暴露 `toapi` 的上下文；脚本以 async IIFE 编译执行，`toapi.request.send` / `toapi.env.set` 通过消息回宿主，由宿主的 HttpEngine 与 Repo 落地，因此脚本内的子请求与手动请求共享同一套伪装、代理、CookieJar 与历史入库路径。worker 结束即销毁，运行时变量通过 `done` 消息回传宿主，供链式后续接口插值。

脚本编辑器的静态检查：检测到 `fetch(`、`require(` 等直接画红线提示"沙箱中不可用，请使用 toapi.request.send"。

## 7. 示例：登录 → 带 Token 查询

```js
// 接口「查询订单」的 pre_script
const login = await toapi.request.send({
  method: 'POST',
  url: toapi.vars.get('baseUrl') + '/api/login',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    username: toapi.vars.get('username'),
    sign: toapi.md5(toapi.vars.get('password') + toapi.timestamp())
  }),
  fake: { ua: '@preset:okhttp' }
})

toapi.test('登录成功', () => toapi.expect(login.status).toBe(200))
const token = login.json().data.token
toapi.vars.set('token', token)
toapi.request.setHeader('Authorization', 'Bearer ' + token)
```
