# ToAPI — 测试实施规范（单元 / 集成 / E2E）

> 07 号文档定义"测什么"（用例清单与发布门禁），本文档定义"怎么写"：
> 目录、命名、夹具、靶场、隔离、确定性、覆盖率、CI 流水线。

## 1. 总览

| 层 | 工具 | 目录 | 运行 |
|---|---|---|---|
| 单元 | Vitest | `tests/unit/**` | `npm run test:unit`（watch 可用） |
| 集成 | Vitest + 本地靶场 + 临时 DB | `tests/integration/**` | `npm run test:integration` |
| 沙箱 | Vitest（worker 沙箱用例并入 integration） | `tests/integration/script/**` | `npm run test:integration`（Python 用例待 M5） |
| E2E | Playwright（Electron） | `tests/e2e/**` | 计划中；当前用 CDP 驱动真机（下一行） |
| 真机流程 | CDP 驱动 Electron（含脚本断言与 Runner） | `scripts/verify-flow.mjs` | `npm run verify:flow` |
| 产物冒烟 | CDP 驱动已打包 exe | `scripts/smoke-package.mjs` | `node scripts/smoke-package.mjs release/win-unpacked/ToAPI.exe` |
| 契约 | `scripts/check-channels.ts` | CI 步骤 | `npm run check:channels` |
| 一键门禁 | typecheck + lint + format + channels + tests | `package.json` | `npm run gate` |

`vitest.config.ts` 用 projects 分三套环境（unit=node 无 IO、integration/sandbox=node 有 IO），互不串场。

## 2. 单元测试标准

### 2.1 适用范围
纯函数与纯类：`vars/resolver`、`vars/extractor`、`codegen/*`、`tapi/checksum`、cron 解析、聚合器、脱敏中间件、schema。

### 2.2 编写规则
- 文件镜像被测路径：`electron/vars/resolver.ts` → `tests/unit/vars/resolver.test.ts`。
- 命名：`describe('VarResolver.resolve')` + `it('循环引用时返回错误而非死循环')`（中文描述行为）。
- 一个 it 一个断言主题；用表驱动覆盖等价类：
```ts
it.each([
  ['{{a}}', { a: '1' }, '1'],
  ['{{missing}}', {}, '{{missing}}'],   // 未命中保留原文
])('resolve(%s)', (input, vars, out) => { ... })
```
- 禁 mock 纯函数自己的依赖之外的东西；纯函数本不该有依赖。
- 快照仅限转换类（codegen 往返、TAPI 导出），快照文件入库评审。

## 3. 集成测试标准

### 3.1 本地 HTTP 靶场（`tests/fixtures/range-server.ts`）
- 每次集成 run 起独立实例，随机端口；路由覆盖：GET/POST/echo-headers/redirect 链/cookie 种植/慢响应（可控延迟）/大 body/TLS 自签。
- 靶场记录收到的原始请求（method、有序 headers、body），测试直接断言"线上真实行为"——伪装、Header 顺序、代理生效只能这样验（07 号文档硬规则）。

### 3.2 DB 隔离
- 每个测试文件 `tmp db`：`openDatabase(tmpdir())` + 跑全量迁移；`afterEach` 清表或整体删库文件。
- 禁止共享全局 DB 单例进测试；Repo 一律构造注入。

### 3.3 典型用例骨架
```ts
it('代理开启后请求经代理且 UA 被伪装覆盖', async () => {
  const range = await startRange()                 // 靶场
  const proxy = await startRecordingProxy(range)   // 计数代理
  const engine = new HttpEngine(...)
  await engine.execute(finalReq({ fake: { ua: '@preset:okhttp', proxy: { enabled: true, url: proxy.url } } }))
  expect(proxy.count).toBe(1)
  expect(range.lastRequest.headers['user-agent']).toContain('okhttp')
})
```

## 4. 沙箱测试标准

- JS：死循环 → SCRIPT_TIMEOUT 且主进程存活；`fetch/require/process` 不可达；子请求深度/总数限制；`skip()` 语义。
- Python：mock python 可执行（脚本模拟 stdio 协议）跑协议正确性；真 python 跑端到端冒烟（CI 有 python 的 job）。
- 每个沙箱测试必须断言"应用未被拖死"：超时用例后紧跟一个正常用例验证引擎仍可用。

## 5. E2E 测试标准（Playwright + Electron）

### 5.1 结构与稳定化
- Page Object：`tests/e2e/pages/{TreePage,EditorPage,ResponsePage,RunnerPage}.ts`，选择器只用 `data-testid`（禁文案/CSS 选择器）。
- 每 spec 独立 `userData` 临时目录（第二实例必须独立 user-data-dir）；全局 beforeAll 起靶场。
- **禁 `waitForTimeout`**：一律 `expect.poll` / `waitForSelector` / 等待特定 IPC 回执暴露的 UI 态。
- 时间敏感断言放宽到区间（如耗时 >0 而非精确值）。
- Electron 可见性陷阱：`visibilityState` 在自动化下不可信，依赖可见性的逻辑用 CDP `Emulation.setFocusEmulationEnabled` 或真实窗口验证。

### 5.2 黄金路径 spec（每次发版必跑）
`golden-path.spec.ts`：建项目 → 建集合 → 建接口（指向靶场）→ 保存 → 发送 → 断言响应面板 → 写断言脚本 → 跑集合 Runner → 看报告 → 导出 TAPI → 清空 → 导入 → 再跑通。
覆盖即 M1–M5.5 验收链；失败即阻塞发版。

### 5.3 视觉/规范校验
- 关键页面截图入快照仓（阈值 0.1% 容差）；`verify:flow` 当前产出 `.tmp/toapi-flow-1.png`（首轮）、`.tmp/toapi-flow-2.png`（重启后）、`.tmp/toapi-select.png`（下拉展开）与 `.tmp/toapi-titlebar.png`（最大化状态），供人工目检。
- 扫描渲染产物无 emoji codepoint（06 号文档 §3.8 的机器校验）。
- `verify:flow` 内置的规范断言（失败即退出非 0）：
  1. 字号集合 ⊆ {12, 13, 14, 20}；所有可见 `button` 带 `title`；聚焦态 2px ink 外描边
  2. 按钮圆角按角色校验：动作药丸 999px、`.win-btn` 8px、`.palette-item` 8px、`.menu-item` 6px、`.text-tabs` 0px，其余 999px
  3. 计算样式扫描渐变/`box-shadow` 计数为 0（Toast/菜单/面板允许的例外同样为 none）
  4. 画布/浮层：`body` 底色 `rgb(242,242,244)`；`.tree/.workspace/.response-col` 白底、1px 边框、14px 圆角；`.shell` gap/内边距 10px；选中文字 Tab 透明底、0 圆角、2px 下划线 `rgb(22,22,24)`
  5. 状态行文案匹配 `200 OK · Nms · X B`，底栏匹配 `DB .+` 与 `v<package.version>`
  6. JSON key=`rgb(22,22,24)`、string=`rgb(29,78,216)`、number/bool=`rgb(180,83,9)`
  7. 右键菜单 10px/无阴影/危险项 `rgb(200,30,30)`；命令面板 14px/无阴影
  8. 1024×640 下 `.tree`、`.workspace`、`.response-col` 不重叠，URL ≥200px（实测 237px）
  9. 无边框标题栏：高 46px、整条 `-webkit-app-region: drag`、控件 `no-drag`、三枚 32×28/8px 按钮带 `title`；点击最大化/还原/最小化后用 Win32 `GetWindowPlacement`（`scripts/window-state.ps1`）断言真实 `windowState`，最大化图标同步为 `restore`
  10. 标题栏截图归档 `.tmp/toapi-titlebar.png`（含最大化后状态）
  11. 下拉列表：CDP 可信点击展开后 `::picker(select)` 圆角 10px、无阴影，选项 999px；截图 `.tmp/toapi-select.png`
  12. Toast 底部居中（距底 30–80px，实测 44px）、999px 圆角
  13. 交互闭环：确认框文案、拖拽排序、栏宽与方向偏好重启后仍存在
- 现有 CDP 脚本的点击助手按 `title` 找控件（对应用户悬浮提示），几何与样式断言用 `data-testid`/CSS；新增用例优先 `data-testid`。
- 退出应用用 CDP `Browser.close` 并等待进程退出，确保 Chromium 把 `localStorage` 刷盘后再断言重启持久化。

## 6. 确定性纪律（所有层共享）

- 禁真实时钟：cron/调度/超时测试用假时钟（vi.useFakeTimers）或注入时钟接口。
- 禁真实网络：除靶场与显式标记 `@online` 的用例（默认排除，夜间任务跑）。
- 禁测试间顺序依赖；可任意单跑、并发跑。
- flaky 处理：重试 1 次仍失败 → 标记 `fixme` 并建任务，禁止无限 retry 掩盖。

## 7. 覆盖率与门禁

| 对象 | 行覆盖门槛 |
|---|---|
| `shared/`、`vars/`、`codegen/`、`tapi/`、`schedule/cron` | ≥ 90% |
| `flow/`、`http/`、`script/` | ≥ 80%（不足部分必须有集成/E2E 用例链接） |
| UI 组件 | 不强制行覆盖，关键交互必须有 E2E |
- PR 门禁：lint → typecheck → check-channels → unit → integration（sandbox 可并行）。
- 夜间任务：sandbox 全套 + e2e 全套 + `@online` + 压测引擎长跑回归（13 号文档 §3）。
- 发版门禁：07 号文档 §4 检查单 + golden-path 全绿。

## 8. 测试数据与夹具

- `tests/fixtures/`：示例 TAPI 文件（含各 format_version）、示例 `.tapi.md`、MD 接口文档样本、curl/JS/Python 代码样本、dataFeed CSV。
- 夹具即文档：新增格式能力时必须同步加夹具样本，解读/转换用例直接消费它们。
- 含密钥样式数据的夹具用假值（`password=FAKE_SECRET_123`），脱敏测试用其扫描断言。
