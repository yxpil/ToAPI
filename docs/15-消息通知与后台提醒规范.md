# ToAPI — 消息通知与后台提醒规范

> 测试跑完要主动说话：定时回归失败、压测阈值破位、宏执行中断……
> 通知体系 = 事件源 → 订阅规则 → 多通道投递（应用内 / OS 原生 / Webhook）→ 通知中心留痕。

## 1. 事件源与通知类型

| 事件 | 默认级别 | 说明 |
|---|---|---|
| Runner 完成 | info / warn（有失败时） | 标题含通过率：`订单回归：48/50 通过` |
| Runner 失败（stopOnFail 中止） | error | |
| 定时任务触发完成 | 跟随结果 | 任务名 + 结果摘要 |
| 定时任务 misfire 补跑 | warn | 「应用未运行错过 2 次，已补跑最近一次」 |
| 节点代为测试完成 | info / warn（有失败时） | 事件名 `node.finished`，标题 `<节点名>：48/50 通过`，正文列前 3 个失败接口；来源 `runner_run`（本机落地的远端运行）（24 号文档 §4） |
| 节点代为测试超时 | error | 10 分钟未回传结果即停止等待并 `force` 投递（远端可能仍在跑），不受"状态未变则静默"约束 |
| 动作宏失败 | error | 含失败步骤序号 |
| 压测完成 / 阈值破位 | info / error | 附 p95、错误率、verdict |
| 压测自动暂停 | warn | 错误率熔断触发 |
| 外部通道异常 | warn | Local API 连续 401、MCP 未授权连接尝试 |
| DB 迁移/备份失败 | error | 启动期关键错误 |

级别映射 UI：`info` 黑字、`warn` 橙（`--warn`）、`error` 红（`--err`）；图标为 SVG（bell/info/alert-triangle/alert-octagon），遵守 06 号文档 §3.8。

## 2. 通知模型（追加进 03 号文档）

`notification` 表：
| 列 | 说明 |
|---|---|
| id | ULID |
| type | 事件类型（§1 左列机器名，如 `runner.finished`） |
| level | `'info' / 'warn' / 'error'` |
| title / body | 标题与摘要（body 截断 500 字符） |
| source_type / source_id | 关联对象（`runner_run` / `schedule_task` / `load_run` / `macro`） |
| read | 0/1 |
| count | 60s 合并窗口内累计的条数，首条为 1；合并只更新这一条记录的 `level/title/body/count`（§3.2） |
| created_at | |
索引：`(read, created_at DESC)`、`(type, created_at DESC)`；保留最近 1000 条环形清理。

## 3. 投递通道（可各自开关，按事件类型订阅）

| 通道 | 行为 | 适用 |
|---|---|---|
| 应用内 Toast | 窗口底部居中黑底白字药丸 2s（success=check / error=cross 前缀，error 需手动关） | 窗口在前台时 |
| 通知中心 | 全部事件必入（§2 表），底栏铃铛图标 + 未读角标 | 留痕回看，**不可关** |
| OS 原生通知 | Electron `Notification` API；仅当窗口失焦/最小化到托盘时投递，前台不打扰 | 后台任务结果 |
| 声音 | 不单独发声：它映射成 OS 通知的 `silent` 取反（`sound=1` → 非静默通知），勿扰与音量完全交给系统裁决 | 可选 |
| Webhook | POST JSON 到用户配置 URL（企业微信/钉钉/飞书机器人格式预设 + raw JSON 自定义） | CI 群通知 |

### 3.1 订阅规则
设置页按事件类型 × 通道勾选矩阵；默认：前台只 Toast，后台补 OS 通知，error 加声音，Webhook 默认全关。
`notify.rules` 存 `app_settings`：`{eventType: {toast:1, os:1, sound:0, webhook:1}}`，与托盘/状态变化开关（`notify.channels`）一起由 `notify:get-settings` / `notify:set-settings` 一对通道读写（§6）。

### 3.2 聚合与防轰炸
- 相同 type 60s 内多次触发合并为一条：「订单回归等 3 个任务完成：2 通过 1 失败」。
- Webhook 单独限流：每 URL 每分钟最多 6 条，超出合并为摘要。
- 定时任务高频场景（如每分钟探测）：默认只通知**状态变化**（上次成功这次失败才发），可选"每次都发"。

### 3.3 Webhook 载荷
```jsonc
{
  "app": "ToAPI",
  "type": "runner.finished",
  "level": "warn",
  "title": "订单回归：48/50 通过",
  "body": "失败：创建订单(500)、支付回调(超时)",
  "run_id": "...",
  "ts": 1761206400000
}
```
预设模板负责转成各 IM 机器人格式；secret 值永不进载荷；Webhook URL 视为敏感配置，UI 掩码显示。

## 4. 后台运行

- 设置项「关闭窗口时最小化到托盘」（默认开）：托盘驻留；托盘图标用应用标识缩到 16×16，有待处理 error 未读时在右下像素级叠加红点（位图绘制，非 emoji），界面里的铃铛才用 SVG 图标（06 号文档 §3.8）。
- 托盘菜单：打开主窗口、显示最近 3 条通知摘要、立即运行任务子菜单、退出。菜单在每次新通知入库与关窗收进托盘时重建。
- 关窗只隐藏不销毁：`win.close()` 被 `preventDefault` 后 `hide()`，只有托盘「退出」与 `app.quit()` 走真退出路径，所以定时任务在窗口关掉后仍按计划跑。
- 无头任务完成（系统级唤醒场景，12 号文档 §2）：无窗口时只写通知中心 + Webhook；下次开 GUI 弹未读汇总。（依赖 §2 的系统级唤醒，尚未实现）
- 系统勿扰/专注模式：OS 通知由系统决定是否展示，应用不强行弹出；通知中心与 Webhook 不受勿扰影响。

### 4.1 平台差异（v0.4.1 实测）

| 项 | Windows | macOS | Linux |
|---|---|---|---|
| 「关窗最小化到托盘」默认 | 开 | 开 | **关** —— GNOME 等常无可用状态栏托盘，默认隐藏窗口等于把应用藏没；用户在通知设置里可手动打开 |
| 隐藏后定时器 | 正常 | 需要 `powerSaveBlocker.start('prevent-app-suspension')`，否则 App Nap 把主进程定时器降频到分钟级，定时回归不准点（收进托盘时开启，唤回窗口即释放） | 正常 |
| 隐藏后界面可被 CDP 驱动 | 是 | 否（窗口进程被系统降频） | 是 |
| 关最后一个窗口的进程语义 | 退出（托盘关闭时） | 不退出，留在 Dock（mac 惯例，托盘驻留与否都一样） | 退出（托盘关闭时） |
| 托盘红点位图 | 已验证 | 同一套 BGRA 位图代码，未在真机验证 | 依赖桌面环境的 StatusNotifier 支持 |

## 5. UI 落点（遵循 06 号文档）

- 底栏右侧铃铛按钮（SVG，h=30 药丸 hover），未读数角标为黑色小圆点+白字数字。
- 通知中心：右侧抽屉 320px，按时间分组（今天/昨天/更早），条目 = 级别图标 + 标题 + 相对时间 + 摘要；点击跳转对应来源（run 报告/任务/压测详情）。
- 抽屉顶部：「全部已读」Ghost 按钮 + 按类型筛选药丸 Tab。

## 6. IPC（追加进 04 号文档 §3.5）

| Channel | 说明 |
|---|---|
| `notify:list` | 游标分页 + 未读过滤 + 按类型筛选，返回 `{items, nextCursor, unread}` |
| `notify:mark-read / notify:mark-all-read` | 返回 `{unread}`，角标与抽屉共用 |
| `notify:get-settings / notify:set-settings` | 订阅矩阵 + 托盘/状态变化/Webhook 设置的整体读写；`set-settings` 只覆盖给出的字段 |
| `notify:test-webhook` | `{url, template}` 发一条测试消息验证连通，回传 `{ok, status, error}` |
| `event:notify` | 主进程 → 渲染进程推送新通知（Toast + 角标实时刷新），载荷含 `count` |

## 7. 测试用例（纳入 07 号文档执行清单 §2.12）

- 事件→通知：§1 每种事件触发后通知中心有记录、级别正确、source 跳转可达
- 通道矩阵：订阅规则每个组合生效；前台时不发 OS 通知；托盘态发 OS 通知
- 聚合：60s 窗口合并计数正确；Webhook 限流 6/min；状态变化模式只在翻转时通知
- 脱敏：Webhook 载荷与通知 body 不含 secret 值（用 secret 变量名扫描断言）
- 托盘：关窗最小化、error 红点、托盘菜单最近 3 条正确
- 容量：1000 条环形清理；未读角标 99+ 封顶显示

实现落点：`electron/notify/service.ts`（合并窗口、订阅矩阵、状态变化抑制、Webhook 限流）、
`electron/notify/webhook.ts`（四种模板载荷与地址校验）、`electron/desktop/tray.ts`（托盘、红点位图、菜单、OS 通知）。
用例覆盖见 `tests/integration/notify/channels.test.ts`（18 例，OS 投递用注入的 `desktop` 桩、Webhook 用注入的 `fetch` 桩，其余全走真实 SQLite）与
`tests/integration/schedule/tasks.test.ts`（真实 Runner + 靶场链路的 10 例）。
