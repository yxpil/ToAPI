# ToAPI — 前后端通信实施规范

> 04 号文档定义"契约"（channel 清单与载荷格式），本文档定义"实施"：
> UI 怎么连、怎么订阅、怎么取消、错误怎么落地、大流量怎么走。
> 前后端 = Renderer(UI) ↔ Main(主进程)。

## 1. 通信总览

| 通道类型 | 方向 | 用途 | 底层 |
|---|---|---|---|
| invoke/handle | UI → Main（请求-响应） | 一切 CRUD 与动作 | `ipcRenderer.invoke` |
| event 推送 | Main → UI（订阅） | 进度、通知、实时曲线 | `webContents.send` |
| 文件路径引用 | 双向 | 大 body、报告、Skill 包 | 主进程写文件，UI 经专用 channel 按需读取 |

**禁止**：UI 起 HTTP/WebSocket 直连主进程、renderer 读本地文件、preload 暴露 `ipcRenderer` 本体。

## 2. UI 侧调用标准

### 2.1 三步铁律
```
组件 → store action → invoke() → IpcResult → store 状态 → 组件渲染
```
- 组件里不出现 `window.toapi`、不出现裸 `invoke`；一切经 store。
- 每个 store action 固定处理三态：`pending / success / error(IpcError)`。
- 错误分流表（store 基类统一实现）：

| code | 落点 |
|---|---|
| VALIDATION | 表单字段红标 |
| NETWORK / TIMEOUT / SCRIPT_* | 响应面板错误态 |
| CANCELLED | 静默复位 pending |
| FORBIDDEN / RATE_LIMIT / BUSY | Toast warn |
| DB / 其他 | 通知中心 error 条目 + Toast |

### 2.2 事件订阅生命周期
```ts
// useEvent hook 内部实现要点
useEffect(() => {
  const off = window.toapi.on('event:runner-progress', handler)
  return off                          // 卸载必须退订
}, [runId])                           // 依赖变化重订阅
// StrictMode 双挂载安全：preload 的 on 幂等，重复订阅去重
```
- 订阅粒度按 id 过滤（`runId`/`cancelId` 在 payload 内，store 侧过滤，不在主进程开多路通道）。

### 2.3 窗口控制
- 无边框标题栏的 `window:get-state / minimize / toggle-maximize / close` 统一经 `src/stores/window.store.ts` 中转，组件不直接 `invoke`。
- 最大化状态以主进程为唯一真源：`event:window-state`（双击拖拽区、`Win+↑`、贴边）经 `useEvent` 写回 store；按钮回包的 `{maximized}` 只是乐观值，事件随后校正。

### 2.4 取消
- 发起长操作时生成 `cancelId = ulid()`，存入 store。
- 取消按钮 → `invoke('api:cancel', {cancelId})`；同时本地立即复位 pending（不等回执，乐观取消）。
- 窗口关闭/路由切换时，store 的 `dispose()` 批量取消在途操作。

## 3. Main 侧实施标准

- `IpcRouter.guard` 统一做：zod 校验 → 业务调用 → `IpcResult` 包装 → 日志（脱敏中间件）。
- 事件推送统一经 `EventBus.send(win, channel, payload)`；多窗口场景按窗口订阅表分发。
- 推送频率限制：`event:load-tick` 固定 1s 节流；`event:script-log` 50ms 合批；防止 IPC 洪水打爆 UI。

## 4. 大载荷与二进制

| 场景 | 规则 |
|---|---|
| 响应 body > 1MB | SendResult 只带 `bodyPath`；UI 需要时调 `history:get-body {id, range?}` 分段读 |
| 报告/Skill 包/TAPI 导出 | 主进程写盘返回 `filePath`，UI 展示路径 + 「打开所在文件夹」按钮 |
| 图片/二进制预览 | `media:get {path}` 返回 base64 缩略（>512KB 先降采样） |
| 粘贴上传 body | UI 经 `body:stage` 先把文件交给主进程落临时区，发送时引用 path |

## 5. 版本与兼容握手

- 启动时 UI 调 `app:hello` → 返回 `{mainVersion, schemaVersion, channelsHash, platform, dbSizeBytes}`。
- `dbSizeBytes` 用于底栏 DB 大小（06 号文档 §4），由主进程 `statSync(dbPath)` 实时读取；`:memory:` 库返回 0。UI 在布局变化/手动刷新时重新握手即可刷新该值，无需新增通道。
- `channelsHash` = `shared/channels.ts` 内容的哈希；UI 侧构建期嵌入同值，不一致弹「主进程与界面版本不匹配，请重启」——防热更新/异常替换后契约漂移。
- `schemaVersion` 即 DB 迁移版本，与 03 号文档 `user_version` 对应。

## 6. UI 功能 → 接口对照表（要用哪些接口）

| UI 模块 | invoke 通道 | event 通道 |
|---|---|---|
| 项目树 | `project:*` `collection:*` `api:create/duplicate/delete` `tree:move` | — |
| 请求编辑器 | `api:get/update` `env:*` `var:*` `api:send` `api:cancel` | `event:send-progress` `event:script-log` |
| 响应面板 | `history:list/get/get-body` | — |
| 底栏 | `env:list` `var:set` `app:hello` | — |
| Runner 面板 | `runner:start/cancel/report` | `event:runner-progress` |
| 脚本/案例 | `case:run` `codegen:*` `testgen:from-history` `python:detect` | `event:script-log` |
| 协作 | `tapi:*` `md:*` `skill 导出走 tapi:export 变体` | — |
| 任务/宏 | `task:*` `macro:*` | `event:notify`（结果） |
| 压测 | `load:run/cancel/get/compare` | `event:load-tick` |
| 通知中心 | `notify:*` | `event:notify` |
| AI 助手 | `ai:*` | — |
| 设置 | `open:*` `notify:get/set-rules` `ai:get/set-config` `app:hello` | — |

## 7. 校验脚本（CI）

`scripts/check-channels.ts` 在 CI 执行：
1. `shared/channels.ts` 每个 key 在 `router.ts` 有注册
2. 每个 key 在 preload 白名单
3. 04 号文档 channel 表与代码清单 diff 为空
4. `event:*` 通道在 preload `on` 白名单
任一失败阻塞合并。
