## 0. 共享类型层（唯一事实源）

`shared/`（main 与 renderer 都 import，零运行时依赖）：
```
shared/
├─ types.ts        # Project/Collection/ApiDetail/SendResult/RunnerRun...（04 号文档全部类型）
├─ channels.ts     # 全部 channel 名的常量与载荷类型映射表（见 §1.2）
└─ schemas.ts      # zod schema，IpcRouter 与前端表单校验共用
```

## 2. 领域服务（electron/flow/*）

### 2.1 RequestFlow `electron/flow/request.ts`
```ts
export class RequestFlow {
  constructor(private http: HttpEngine, private vm: ScriptVM, private vars: VarResolver,
              private repo: Repo, private events: EventBus, private cancel: CancelRegistry) {}
  async send(input: SendInput): Promise<SendResult>        // 时序见 17 号文档 §3.1
  async sendSub(req: SubRequest, ctx: RunCtx): Promise<SubResponse>  // 脚本子请求入口，深度/总数计数在 ctx
  cancel(cancelId: string): void
}
```
错误路径：每步包 `Result`，失败即短路返回，已产生日志/快照随错误返回；`skip()` 抛内部 `SkipSignal` 不算错误。

### 2.2 RunnerFlow `electron/flow/runner.ts`
```ts
export class RunnerFlow {
  async start(input: RunnerStartInput): Promise<{ runId: string; total: number }>  // 立即返回，执行在后台
  cancel(runId: string): void
  whenDone(runId: string): Promise<void> | undefined   // 无头 CLI 等收尾；UI 靠事件，不取这个 promise
  private async loop(args: { targets, rows, iterationCount, input, state }): Promise<void>
  // 外层按迭代（rows[i % rows.length]），内层按 sort_order；逐项 → RequestFlow.send → runner_item 落库
  //   → event:runner-progress → stopOnFail 判断；nextRequest 决定跳转或结束本轮
}
```
- 迭代次数：`iterationCount ?? (rows.length || 1)`；`total = 接口数 × 迭代次数` 是计划值，`setNextRequest` 截断后实际条目可少。
- 每轮开始取该行数据注入 `RequestFlow`，运行时变量整个 run 只清一次（`clearSession`），保证链式提取跨轮可追溯。
- `setNextRequest` 跳转次数上限 `接口数 × 20 + 20`，超限记 `error` 条目并终止本轮。

### 2.2b CLI `electron/cli/*`（23 号文档 §5.3）
```ts
// args.ts：解析 → CliOptions；任何用法问题抛 CliUsageError（退出码 2）
export const parseArgs = (argv: string[]): CliOptions
// main.ts：不开窗口，直接 createKernel（临时库或 --db）+ RunnerFlow
export const runCli = (argv: string[]): Promise<0 | 1 | 2>
// reporters.ts：纯函数渲染，单测可直接断言字符串
export const renderJson / renderJunit / renderHtml / itemLine
```
- 装配顺序：导入集合（Postman v2.1；`.tapi` 在 M5.5 前明确拒绝）→ 选项目/集合范围 → `--globals` 落全局变量 → `--env`（文件或库内名称）激活 → `--data` 解析成行 → `runner.start()` → `await whenDone()` → 读 `runner.get()` 出报告。
- 退出码：0 全通过（允许跳过）；1 有失败/错误；2 用法、文件不可读、导入失败。`runCli` 自身不 `process.exit`，由 `bin/toapi.cjs` 落 exitCode，便于集成测试直接调用。

### 2.3 TaskFlow / MacroPlayer `electron/schedule/*`
- `scheduler.ts`：`class Scheduler { start(); stop(); private tick() }`，基于 `setInterval(1s)` + 单调时钟对比 `next_run_at`；cron 解析器纯函数 `nextRuns(expr, from, count): number[]`（独立可测）。
- `macro.ts`：`class MacroPlayer { run(macro: ActionMacro): Promise<MacroResult> }`，步骤执行经 `control-whitelist.ts` 校验；UI 操作经 `event:macro-op` 指令渲染进程执行并回执（主进程不直接碰 DOM）。

### 2.4 LoadFlow `electron/load/*`

### 3.5b 定时调度 `electron/schedule/*` + 托盘 `electron/desktop/tray.ts`（12 号文档）

### 3.7 TapiCodec `electron/tapi/*`（08 号文档）
```ts
// format.ts：纯类型 + 两个纯函数，导出与导入必须共用同一实现
export const canonicalJson = (value: unknown): string     // key 字典序递归排序、无空白
export const checksumOf = (payload: TapiPayload): string  // 'sha256:' + hex(sha256(canonical))
// export.ts：读库 → TapiFile（导出内 ID 用 col-N / api-N 临时键）
export const buildTapi = (repos: Repos, input: BuildTapiInput): { file; stats; containsSecrets }
// import.ts：外部 JSON 逐字段收窄成 TapiFile，再在同一事务里落库
export const readTapi = (text: string): TapiFile
export const inspectTapi = (repos: Repos, file: TapiFile): TapiInspection
export const importTapi = (db: Db, repos: Repos, input: ImportTapiInput): TapiImportReport
// service.ts：读写盘与对话框编排，通道只做转发
export class TapiService { export(); inspect(); import() }
```
- 连接关系：`ipc/handlers` 只做参数转发；GUI（`src/features/tapi/TapiImport.tsx`）与 `electron/cli/main.ts` 都经 `kernel.tapi`，不各自实现导入 —— 与 Runner/CLI 同源同构（17 号文档 §1）。
- 边界约束：外部输入一律走 `readTapi` 的字段收窄，不做整体 cast；`supported=false` 或 `checksumOk=false` 时 `import()` 直接抛错（拒绝优先于降级）；`transaction()` 包住全部写库步骤，任何一步失败整体回滚。
- 集合树在库内是 `parentId` 邻接表、在文件里是嵌套 `children`：导入按 `(父路径, 名称)` 建索引判重，导出按 `sortOrder` 保序。

### 3.8 开放通道 `electron/open/*`（11 号文档）
```ts
// tools.ts：唯一的能力表 —— 名字、说明、入参字段、是否执行类、可选 targetUrl（host 闸门取数）
export const OPEN_TOOLS: OpenTool[]

```
- 顺序固定：开关与密码 → 限流 → 参数校验 → 客户端授权（60s 超时按拒绝）→ host 白名单 → 执行 → 脱敏 → 审计。任一步失败都有 `external_call_log` 记录。
- 与 GUI 共用 `kernel`（`createKernel({headless:true})` 起无头实例），不复制业务逻辑；`open:approval-result` 通道 + `event:open-approval` 事件是 GUI 与闸门之间唯一的握手。
- 无界面模式（`toapi mcp`）没有授权条可弹：调用密码即授权，host 越界一律拒绝。

## 4. 渲染进程连接（src/）

### 4.1 IPC 封装 `src/lib/ipc.ts`
```ts
export async function invoke<K extends ChannelName>(ch: K, req: ReqOf<K>): Promise<ResOf<K>> {
  const r = await window.toapi.invoke(ch, req)
  if (!r.ok) throw new IpcError(r.error)          // UI 层统一 catch 点
  return r.data
}
export function useEvent<K extends EventChannel>(ch: K, cb: (p: EventPayload<K>) => void): void
// React hook：挂载订阅、卸载退订，StrictMode 双挂载安全
```

### 4.2 状态与数据流
- Zustand store 按域分片：`useTreeStore / useEditorStore / useRunnerStore / useNotifyStore`。
- 读取路径：组件 → store action → `invoke()` → 写 store；**组件不直接调 invoke**（便于 loading/error 统一处理与测试 mock）。
- 错误映射：store 捕获 `IpcError` → 按 code 分流（VALIDATION 进表单、NETWORK/TIMEOUT 进响应面板、其余进通知中心 error Toast）。
