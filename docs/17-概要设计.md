## 1. 分层与依赖方向

```
┌─ Renderer (React) ─ features/* ─ stores/* ───────────┐
│        只能调用 window.toapi.*（preload 白名单）        │
├─ Preload ─ contextBridge ─────────────────────────────┤
├─ Main ────────────────────────────────────────────────┤
│  IpcRouter → 领域服务层 → 基础设施层                    │
│  领域服务: RequestFlow RunnerFlow LoadFlow TaskFlow    │
│           TapiFlow MdFlow CodegenFlow AiFlow           │
│  基础设施: HttpEngine ScriptVM PyBridge Repo           │
│           VarResolver Notifier Scheduler McpServer     │
├─ SQLite (better-sqlite3, 仅 Repo 层触碰) ──────────────┤
└────────────────────────────────────────────────────────┘
```

**依赖方向铁律**：Renderer → Preload → IpcRouter → 领域服务 → 基础设施 → Repo。
禁止反向依赖、禁止跨层直连（如领域服务直接写 SQL、Renderer import 主进程模块）。

## 2. 模块责任矩阵

| 模块 | 拥有 | 依赖 | 对外暴露 |
|---|---|---|---|
| `ipc/router` | channel 注册表、zod 校验、IpcResult 包装 | 全部领域服务 | `registerAll(ipcMain)` |
| `flow/request` | 单次发送全流程编排（插值→pre→发送→post→提取→入库） | HttpEngine, ScriptVM, VarResolver, Repo | `send(input): SendResult` |
| `flow/runner` | 集合/项目/单接口串行执行、数据驱动迭代、`setNextRequest` 跳转、进度事件、报告 | RequestFlow, Repo, `onRunFinished` 回调（由内核接 NotifyService） | `start(scope): runId`、`whenDone(runId)`、`cancel(runId)` |
| `flow/data-file` | CSV(RFC4180/BOM) 与 JSON 数据文件解析成迭代行 | —（纯函数） | `readDataFile(path)`、`parseData(text, format)` |
| `cli/*` | `toapi run` 无头入口：参数解析、临时库或 `--db`、导入资产、跑 Runner、出报告与退出码 | kernel（RunnerFlow, PostmanService, Repo） | `runCli(argv): Promise<0\|1\|2>` |
| `http/engine` | undici 封装、伪装应用、代理、CookieJar、取消 | — | `execute(finalReq): RawResponse` |
| `script/vm` | 独立 worker 内的 vm 容器、熔断、toapi/pm 桥接 | HttpEngine（子请求经 RequestFlow 回调） | `runPre/runPost/runCase` |
| `script/pybridge` | Python 子进程 stdio JSON-RPC | 同上 | 同上接口（双语言对齐） |
| `vars/resolver` | `{{var}}` 插值、循环引用检测 | Repo（读变量） | `resolve(text, ctx)` |
| `vars/extractor` | JSONPath/regex 提取 | — | `extract(extractors, response)` |
| `db/repo/*` | 全表 CRUD、事务、迁移 | node:sqlite | 每实体一个 Repo 类 |
| `tapi/*` | `.tapi` 导出/预览/导入（策略与判重）、规范化 JSON 与 checksum | Repo, Db 事务 | `TapiService.export / inspect / import`（GUI 与 CLI 共用，08 号文档 §9） |
| `postman/*` | Collection v2.1 / Environment 解析与生成、source_json 回填、导入报告 | Repo | `inspect / import / exportCollection / exportEnvironment`（B4 增 Apifox 桥，23 号文档 §7.1） |

| `codegen/*` | api↔code 双向、testgen 三路合并 | —（纯函数） | `fromApi / toApi / genTests` |
| `open/*` | 能力清单（工具表）、调用密码闸门、限流、客户端授权、host 白名单、脱敏、审计、Local HTTP API、MCP（stdio/HTTP）、SKILL.md 生成 | 领域服务（只读 + 执行子集），Repo | `OpenService.invoke(tool, params, meta, secret)`、`LocalHttpApi`、`McpSession`、`buildSkillFiles` |
| `schedule/*` | cron/interval/once 触发计算、overlap（skip/queue/parallel）与 misfire（补跑/跳过）策略、锁环境闸门、触发后汇报与报告落盘 | RunnerFlow, NotifyService, FileStore, Repo | `list/create/update/toggle/remove/preview/runNow`、`start/stop`（系统唤醒与宏回放未实现，12 号文档 §6） |
| `load/*` | VU 池、dataFeed、1s 桶聚合 | HttpEngine, Repo, Notifier | `start/cancel`（未实现） |

| `ai/*` | OpenAI 兼容客户端、脱敏、草稿流 | Repo | `generate / explain` |

## 3. 关键时序

### 3.1 单次发送（RequestFlow）
```
UI send → api:send → IpcRouter(zod) → RequestFlow.send
  1. Repo.loadApi(apiId) / 收 draft
  2. VarResolver.resolveAll（env→global→runtime，循环检测）
  3. ScriptVM.runPre（可改 draft / skip / 子请求回调 RequestFlow.sendSub）
  4. HttpEngine.execute（伪装合并: 项目默认 ← 接口覆盖 ← 脚本 fake）
  5. Extractor.extract → runtime vars
  6. ScriptVM.runPost + assertions
  7. Repo.saveHistory（大 body 落文件）
  8. IpcResult.ok(SendResult) → UI
任何一步失败：包装为对应 code（SCRIPT_ERROR/NETWORK/...），已产生的日志随结果返回。
```

### 3.2 集合 Runner（RunnerFlow）
```
runner:start → 建 runner_run → 按 sort_order 取接口列表
  loop: RequestFlow.send（共享 runtimeCtx）→ runner_item 落库
        → event:runner-progress 推送 → stopOnFail 判断
  结束 → report_json 汇总 → Notifier.emit('runner.finished') → IpcResult
```

### 3.3 定时触发（ScheduleService）
```
start() → recover()：库里 next_run_at 已过 → 按 misfire 策略补跑最近一次（warn 通知）或跳过
tick(默认 1s，判定用 process.hrtime 单调时钟)
  → 到期任务 → 先把 next_run_at 推到下一轮（长跑/慢请求都不会被重复排上）
  → overlap：skip 丢弃 / queue 排队（上限 3）/ parallel 并发
  → RunnerFlow.start(scope, 锁定 envId) → await whenDone(runId)
  → notify.report≠none 时 report/export.writeReport() 落盘
  → markRun(last_run_at/last_run_id/last_failed，once 任务置 enabled=false)
  → NotifyService.publish('task.finished', stateKey=task:id) → 通知中心 + OS + Webhook
```
任务触发的运行不发 `runner.*` 通知（RunnerFlow 的 `onRunFinished` 见到 `task:` 前缀就跳过），一次运行只有一条汇报。

### 3.4 AI 草稿流（AiFlow）
```
ai:gen-script → AiClient（prompts 组装+脱敏）→ Provider
  → draft.ts 解析为结构化草稿 → 返回 UI 待确认
  → 用户采纳 → ai:adopt → Repo 写库 + ai_call_log.adopted=1
```

## 4. 数据所有权

| 数据 | 唯一写者 | 读者 |
|---|---|---|
| 项目树/接口/环境 | Repo（经领域服务） | 全部 |
| runtime 变量 | RequestFlow（内存 Map，Runner 生命周期） | ScriptVM, Extractor |
| history | RequestFlow | UI, OpenAPI |
| notification | Notifier | UI |
| 文件（body/report/skill 包） | 各 Flow 经 `infra/filestore` | Repo 存路径 |

跨模块共享数据只允许两条路：**函数参数传递** 或 **Repo 落库**；禁止主进程全局可变单例存业务数据（配置类只读缓存除外）。

## 5. 横切关注点

| 关注点 | 统一方案 |
|---|---|
| 错误 | 全部收敛为 `IpcResult.err`；主进程内部用 `Result<T>` 类型传递，禁止裸 throw 穿越层边界 |
| 日志 | `infra/logger`（electron-log），模块名前缀；secret 值过滤中间件强制启用 |
| 取消 | 每个长操作携带 `cancelId`，`infra/cancel-registry` 统一登记，RequestFlow/RunnerFlow/LoadGen 轮询或 AbortSignal |
| 事件 | 主进程 → UI 仅 `event:*` 三类通道（send-progress / runner-progress / notify / load-tick），经 preload 白名单 |
| 配置 | `app_settings` 单表 + `infra/config` 只读缓存，改配置经 IPC 失效缓存 |
