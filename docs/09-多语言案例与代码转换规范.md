# ToAPI — 多语言案例与代码转换规范

> 三种能力互为闭环：
> ① App 内可用 **JS / Python** 编写并运行请求案例；
> ② 任何接口可一键**生成 JS / Python / cURL 案例代码**给外部门；
> ③ 真实响应/案例代码可**自动转换为测试断言**，回流进 App 变成可重复跑的用例。

## 1. 双语言运行时架构

```
┌─ App 内案例运行 ────────────────────────────────┐
│ JS 案例   → isolated-vm 沙箱（现有管道，05号文档） │
│ Python 案例 → CPython 子进程 + toapi-py SDK      │
│              ↑ stdio JSON-RPC 桥                 │
│              主进程桥接器转发到 HttpEngine         │
└─────────────────────────────────────────────────┘
```

**关键决策：Python 案例的网络请求同样走主进程 HttpEngine**，不直连。
这样 JS 与 Python 案例共享同一套伪装 / 代理 / CookieJar / 历史入库 / 熔断管道，行为完全一致。

- Python 解释器：设置中配置路径（自动探测 `python`/`py -3`），要求 ≥3.9。
- `toapi-py` SDK 随应用内置（`resources/toapi_py/`），启动案例时注入 `PYTHONPATH`，用户零安装。
- 子进程限制：单案例 60s 超时（可配）、内存由系统托管 + 主进程 watchdog、子请求同样受深度/总数限制（桥接层计数）。

## 2. 案例（Case）模型

案例 = 一段可运行代码 + 绑定的上下文，存 DB 新表 `case`：

| 列 | 说明 |
|---|---|
| id / collection_id / name / sort_order | 常规 |
| lang | `'js'` / `'python'` |
| code | 案例源码 |
| bound_api_id | 由哪个接口生成（可空，手写案例为空） |
| env_lock | 是否锁定运行环境（跨部门交付时锁 staging） |

案例在树中与接口同级展示，图标区分语言；点击"运行"即走 §1 管道，结果写入 `runner_run`（`scope_type='case'`），与集合 Runner 共用报告。

## 3. 案例 SDK API（双语言对齐）

### JS（沙箱内，05 号文档的超集不变）
```js
const res = await toapi.request.send({ method:'POST', url:'{{baseUrl}}/login', body:'...' })
toapi.test('登录成功', () => toapi.expect(res.status).toBe(200))
```

### Python（toapi-py）
```python
from toapi import case

res = case.request.send(
    method="POST",
    url="{{baseUrl}}/login",        # 插值在桥接层完成，与 JS 行为一致
    json={"username": case.vars.get("username")},
    fake={"ua": "@preset:okhttp"},  # 同一伪装管道
)

case.test("登录成功", lambda: case.expect(res.status).to_be(200))
token = res.json()["data"]["token"]
case.vars.set("token", token)
```

对齐规则：
| 能力 | JS | Python |
|---|---|---|
| 发请求 | `toapi.request.send` | `case.request.send` |
| 变量 | `toapi.vars.get/set` | `case.vars.get/set` |
| 环境 | `toapi.env.set` | `case.env.set` |
| 断言 | `toapi.test/expect` | `case.test/expect` |
| 伪装 | 请求参数 `fake={}` | 同名同结构 |
| 日志 | `toapi.log` | `case.log` |
| 工具 | md5/sha256/uuid/timestamp | 同名函数（桥接层计算，保证结果一致） |

## 4. 案例代码生成（导出给外部门）

接口右键 →「生成案例代码」，目标三选一：

| 目标 | 产出 | 依赖 |
|---|---|---|
| cURL | 单条命令 | 无 |
| JS（Node） | `case.js`，基于 `undici`/内置 `fetch` | Node ≥18 |
| Python | `case.py`，基于标准库 `urllib`（零依赖版）或 `httpx`（可选版） | Python ≥3.9 |

生成规则：
- `{{var}}` 在生成时用当前激活环境**就地展开**，并在文件头注释列出变量清单，方便接收方改值。
- 默认生成**独立可跑**版本（不依赖 ToAPI）；勾选「ToAPI 案例格式」则生成可回导 App 的 SDK 版本。
- 伪装配置翻译成对应语言：UA/Header 直写，代理用各语言标准写法，CookieJar 生成注释提示。
- 提取器翻译为生成代码里的解析行（如 Python `order_id = res.json()["data"]["id"]`），保持链式语义。

## 5. 案例代码 → 测试：自动转换（核心闭环）

### 5.1 从真实响应生成断言（response → test）
对任意一条历史/新响应点击「生成测试」：

| 响应特征 | 自动生成断言 |
|---|---|
| status | `expect(status).toBe(200)` |
| Content-Type | `expect(headers['content-type']).toContain('application/json')` |
| JSON body 顶层字段 | 每个字段生成 `toBeDefined()` |
| 叶子标量字段（深度≤3） | 生成 `toBe(value)`，**默认注释掉**，用户按需启用 |
| 耗时 | 生成 `expect(timeMs).toBeLessThan(2000)`（阈值按 P95×3 建议值，可改） |
| 数组字段 | 生成 `expect(list.length).toBeGreaterThan(0)`（注释态） |

生成结果写入接口的 post_script（或独立 tests 段），可编辑；再次生成做**三路合并**：保留用户改过的断言，只增量新增新字段断言，不覆盖。

### 5.2 从代码反向生成接口定义（code → api）
粘贴或导入 cURL / JS fetch / Python requests 代码 → 解析为 ApiDetail 草稿：
- cURL：解析 method/URL/headers/data/`-u` auth。
- JS `fetch`/`axios` 与 Python `requests`/`httpx`：AST 级解析（JS 用 `@babel/parser`，Python 用 AST dump 子进程），支持字面量与简单模板拼接；解析不出的动态部分落进 pre_script 原样保留，并在 UI 标黄"需人工确认"。
- 解析成功后自动建议：「是否从代码中的校验语句生成断言？」（识别 `assert res.status_code == 200` / `expect(...)` 等模式 → 转为 `toapi.test`）。

### 5.3 转换正确性标准
任何方向的转换必须满足**往返等价**：`api → code → api` 后，method/URL/headers/body 语义一致（header 顺序、空值差异可容忍）。测试规范中为每种转换对配快照用例（见 07 号文档 §2.6）。

## 6. 跨部门协作流程（推荐）

```
研发部门：联调接口 → 生成测试断言 → 导出 .tapi（剔除密钥）
   │
   ▼ 文件互传
测试部门：导入 .tapi → 补齐环境变量 → 跑集合 Runner
   │  发现新问题：本地写 Python 案例复现
   ▼
案例回传：导出 case.py 或整个 .tapi → 研发导入直接复现
```

## 7. IPC 契约（追加）

| Channel | 入参 | 返回 |
|---|---|---|
| `case:run` | `{caseId?, code?, lang, envId, cancelId}` | `SendResult[]` + 断言汇总（走 `event:script-log`/`event:runner-progress`） |
| `codegen:from-api` | `{apiId, target:'curl'\|'js'\|'python', standalone:boolean}` | `{code}` |
| `codegen:to-api` | `{code, lang:'curl'\|'js'\|'python'}` | `{draft: ApiDetail, warnings: string[], suggestedTests: string}` |
| `testgen:from-history` | `{historyId, options?}` | `{script, addedAssertions: number}` |
| `python:detect` | `{}` | `{found, version, path}` |
