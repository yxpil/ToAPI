# ToAPI — 开放调用与 AI 协作规范（Local API / MCP / MD Skill）

> ToAPI 不只被人用，也要被程序和 AI 用。三条开放通道，共享同一套能力内核：
> ① **Local HTTP API** —— 脚本/CI/其他系统直接驱动 ToAPI；
> ② **内嵌 MCP Server** —— AI 助手（Qoder/Claude/Cursor 等）以 MCP 工具方式调用；
> ③ **MD Skill 文件** —— 导出"可读的技能说明书"，无 MCP 的 AI 也能照着调。

## 0. 总原则

| 原则 | 落地 |
|---|---|
| 一套内核 | 三条通道全部复用主进程现有管道（HttpEngine/VarResolver/ScriptVM/Runner），只是入口不同 |
| 默认关闭 | 所有开放通道默认 off，用户在设置中显式开启 |
| 最小暴露 | 只监听 `127.0.0.1`；要开局域网访问需二次确认并强制 token |
| 能力收敛 | 开放通道是 IPC 能力的**子集**（读写分离，见 §4），不提供删库、清历史等破坏操作 |
| 可审计 | 每次外部调用写 `external_call_log`（时间、通道、工具、参数摘要、结果、耗时） |

## 1. Local HTTP API

### 1.1 形态
- 主进程内嵌 HTTP 服务，默认 `http://127.0.0.1:4730`，端口可配。
- 认证：`Authorization: Bearer <token>`；token 开启时随机生成 32 字节，显示一次后可重置，存 `app_settings`（不落明文日志）。
- 载荷格式与 IPC 完全一致：成功 `{ok:true,data}` / 失败 `{ok:false,error:{code,message}}`（04 号文档 §2），错误码表复用。

### 1.2 端点（与 IPC channel 一一对应）
| 端点 | 对应 channel | 说明 |
|---|---|---|
| `GET /v1/projects` | `project:list` | |
| `GET /v1/apis?collectionId=` | `api:get` 批量 | |
| `POST /v1/send` | `api:send` | body 同 IPC 入参 |
| `POST /v1/run` | `runner:start` | 同步等待完成返回汇总（CI 友好），或 `?async=1` 返回 runId |
| `GET /v1/run/{runId}` | 运行状态/结果 | |
| `POST /v1/case/run` | `case:run` | |
| `POST /v1/md/interpret` | `md:interpret` | |
| `GET /v1/health` | — | 版本、DB 状态、无鉴权 |

### 1.3 限流与熔断
- 默认 60 req/min，突发 10；超限返回 `429 + {code:'RATE_LIMIT'}`。
- Runner 类长任务并发上限 3，超出排队；队列满返回 `BUSY`。

## 2. 内嵌 MCP Server

### 2.1 两种传输
| 传输 | 用途 | 配置 |
|---|---|---|
| stdio | 本地 AI 客户端拉起 `toapi-mcp` 子进程 | 客户端配置 `"command": "ToAPI.exe", "args": ["--mcp-stdio"]`，无需开端口 |
| Streamable HTTP | 已运行实例被多个 AI 会话复用 | 复用 §1 同一端口 `/mcp` 路径，同 token 认证 |

stdio 模式即使 GUI 未开也能工作（无头拉起主进程核心模块，不开窗口）；GUI 运行时两者可并存。

### 2.2 暴露的 MCP Tools（命名与语义稳定，进版本兼容承诺）
| Tool | 说明 | 类型 |
|---|---|---|
| `toapi_list_projects` | 项目/集合/接口树（浅层，含 id 与名称） | 读 |
| `toapi_get_api` | 接口完整定义（脚本/提取器/伪装） | 读 |
| `toapi_send_request` | 发送接口（apiId 或 draft + envId），返回 SendResult | 执行 |
| `toapi_run_collection` | 跑集合 Runner，返回逐项断言结果 | 执行 |
| `toapi_run_case` | 跑 JS/Python 案例 | 执行 |
| `toapi_run_mddoc` | 运行 `.tapi.md` 文档内测试 | 执行 |
| `toapi_interpret_md` | 解读 MD 接口文档为接口草稿 | 读 |
| `toapi_list_envs` / `toapi_get_env` | 环境变量（secret 值脱敏返回 `***`） | 读 |
| `toapi_get_history` | 按 apiId 查最近请求/响应 | 读 |
| `toapi_set_runtime_hint` | 给后续调用提供变量建议（不写库，仅会话级） | 执行 |

**明确不暴露**：删除项目/接口、修改环境 secret、清空历史、导出含密钥 TAPI。AI 通道只做"读 + 跑 + 会话内变量"。

### 2.3 安全闸门
- 首次连接：GUI 弹授权条「允许 XX 客户端访问？」，记住选择，可撤销。
- 每次 `toapi_send_request` / `toapi_run_*`：若目标 host 不在项目环境声明的 host 清单内，GUI 弹一次确认（防 AI 把数据打到意外域名）。
- secret 变量永不返回明文；脚本日志中含 secret 值时脱敏。
- 全部调用入 `external_call_log`，UI 有「外部调用」面板可回看。

## 3. MD Skill 文件（无 MCP 的 AI 协作）

### 3.1 概念
Skill 文件 = 一份给 AI 看的 Markdown 技能说明书（`SKILL.md` 风格）：frontmatter 描述能力 + 正文给出"何时用、怎么调、参数是什么、示例代码"。AI 客户端（支持 skill 机制的）加载后即可直接调用目标 API——不经过 ToAPI 也能工作。

### 3.2 导出：集合/项目右键「导出 AI Skill 包」
```
订单中心.skill/
├─ SKILL.md          # 技能说明书（见 §3.3）
├─ 订单中心.tapi      # 可选：同内容 TAPI，供有 ToAPI 的一方导入
└─ examples/
   ├─ login.py / login.js / login.sh   # 关键接口的可跑示例
```

### 3.3 SKILL.md 生成模板
```markdown
---
name: order-center-api
description: 订单中心 staging 环境接口调用技能。当需要创建订单、查询订单、
  取消订单或做订单链路回归时使用。baseUrl 见"环境"一节，鉴权走登录接口取 token。
---

# 订单中心 API 技能

## 环境
- baseUrl: https://staging.example.com（如对方给了其他环境，替换即可）
- 变量: {{username}} {{password}} 需向接口提供方索取

## 调用顺序（链式约束）
1. 先调「登录」取 token（见示例 examples/login.py）
2. 后续请求带 Header: Authorization: Bearer <token>

## 接口清单
### 登录 — POST {{baseUrl}}/api/login
请求体: {"username": "...", "password": "..."}
响应: 200 时 data.token 为令牌，有效期 2h
断言建议: status == 200 且 data.token 非空

### 创建订单 — POST {{baseUrl}}/api/orders
...（每个接口一节：方法、URL、头、体、提取器语义、已知坑）

## 验证方式
调完后可用「查询订单」回读确认；或把本目录 订单中心.tapi 导入 ToAPI 一键回归。
```

生成规则：
- 从集合数据自动组装：接口定义、提取器链（推导"调用顺序"节）、断言转为"断言建议"、伪装配置转为注意事项。
- secret 变量只列名字，永不出值；frontmatter `description` 写清"何时用"，这是 AI 选择该技能的唯一依据。
- 生成后可人工编辑，App 不覆盖手改（同 testgen 三路合并原则）。

### 3.4 导入/识别
打开外部收到的 SKILL.md：解析 frontmatter + 接口小节 → 生成项目草稿（复用 10 号文档 MD 解读管道，置信度标记相同）。

## 4. 能力矩阵（三条通道对比）

| 能力 | GUI | Local API | MCP | MD Skill |
|---|---|---|---|---|
| 发送请求 | 有 | 有 | 有 | AI 自行构造 |
| Runner/案例/MD 测试 | 有 | 有 | 有 | 无（只给断言建议） |
| 读项目/环境 | 有 | 有 | 有（脱敏） | 有（文档化） |
| 写环境 secret | 有 | 无 | 无 | 无 |
| 删除/清空 | 有 | 无 | 无 | 无 |
| 导出 TAPI | 有 | 无 | 无 | 包内附带 |

## 5. 数据结构（追加进 03 号文档）

- `app_settings(key TEXT PK, value TEXT)`：开放通道开关、端口、token 哈希、授权客户端清单。
- `external_call_log(id, channel:'http'|'mcp', tool, client, params_summary, ok, error_code, time_ms, created_at)`，保留最近 5000 条环形清理。

## 6. IPC / 测试（追加）

- IPC：`open:get-config` / `open:set-config` / `open:rotate-token` / `open:list-clients` / `open:revoke-client` / `open:call-log`。
- 测试（进 07 号文档 §2.8）：
  - 未带 token / 错误 token 一律 401；限流触发 429；host 白名单外请求触发确认闸门
  - MCP stdio 无头模式可跑通 `list → send → run` 全链；secret 变量任何通道不出明文
  - Skill 包导出：frontmatter 合规、示例代码真实可跑（CI 里对靶场执行 examples）
  - 审计：每次外部调用必有 `external_call_log` 记录且参数摘要不含 secret 值
