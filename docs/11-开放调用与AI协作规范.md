# ToAPI — 开放调用与 AI 协作规范（Local API / MCP / MD Skill）

> ToAPI 不只被人用，也要被程序和 AI 用。三条开放通道，共享同一套能力内核：
> ① **Local HTTP API** —— 脚本/CI/其他系统直接驱动 ToAPI；
> ② **内嵌 MCP Server** —— AI 助手（Qoder/Claude/Cursor 等）以 MCP 工具方式调用；
> ③ **MD Skill 文件** —— 导出"可读的技能说明书"，无 MCP 的 AI 也能照着调。

## 0. 总原则

| 原则 | 落地 |
|---|---|
| 一套内核 | 三条通道全部复用主进程现有管道（HttpEngine/VarResolver/ScriptVM/Runner），只是入口不同 |
| 默认关闭 | 所有开放通道默认 off，用户在设置中显式开启 |
| 最小暴露 | 只监听 `127.0.0.1`；要开局域网访问需二次确认并强制 token |
| 能力收敛 | 开放通道是 IPC 能力的**子集**（读写分离，见 §4），不提供删库、清历史等破坏操作 |
| 可审计 | 每次外部调用写 `external_call_log`（时间、通道、工具、参数摘要、结果、耗时） |

## 1. Local HTTP API

### 1.1 形态
- 主进程内嵌 HTTP 服务（`electron/open/http-api.ts`），默认 `http://127.0.0.1:4730`，端口可配；配置里勾「局域网」才绑 `0.0.0.0`，且必须在设置面板二次确认。
- 认证：**调用密码**（`Authorization: Bearer <密码>`）。库内只存 `salt + scrypt(密码)`，永不存明文；用户可在设置里自定义（≥8 位）或点「生成」拿一次性随机值，`open:rotate-token` 的返回值是明文唯一出现的地方。密码缺失/错误 → 401；未设密码时开关无法打开。
- 载荷格式与 IPC 完全一致：成功 `{ok:true,data}` / 失败 `{ok:false,error:{code,message}}`（04 号文档 §2），错误码表复用。

### 1.2 端点（与工具一一对应，实现在 `electron/open/http-api.ts`）
| 端点 | 对应工具 | 说明 |
|---|---|---|
| `GET /v1/health` | — | 版本、开放通道状态、工具数；**无鉴权**（不含任何数据） |
| `GET /v1/tools` | — | 工具清单 + JSON Schema（需密码） |
| `GET /v1/projects` | `toapi_list_projects` | 项目 → 集合 → 接口树 |
| `GET /v1/project?projectId=` | `toapi_get_project` | 项目定义（根集合 auth / 变量 / 脚本） |
| `GET /v1/apis?projectId=[&collectionId=]` | `toapi_list_apis` | |
| `GET /v1/api?apiId=` | `toapi_get_api` | 含脚本、提取器、伪装 |
| `GET /v1/envs?projectId=` / `GET /v1/env?projectId=[&environmentId=]` | `toapi_list_envs` / `toapi_get_env` | secret 值一律 `***` |
| `POST /v1/send` | `toapi_send_request` | body 同 IPC `SendInput`；受 host 闸门约束 |
| `POST /v1/run` | `toapi_run_collection` | **同步等跑完**返回逐项结果（CI 友好） |
| `GET /v1/run/{runId}` / `GET /v1/runs` | `toapi_get_run` / `toapi_list_runs` | |
| `GET /v1/history?projectId=&apiId=&limit=` | `toapi_get_history` | |
| `GET /v1/skill?projectId=[&environmentName=]` | `toapi_get_skill` | 返回 SKILL.md 正文与示例文件清单 |
| `GET /v1/tapi?projectId=` | `toapi_export_tapi` | 恒定剔除 secret 的 `.tapi` 内容 |
| `POST /mcp` | MCP Streamable HTTP | 与 §2 同一套工具，同 token |

- 状态码：`200` 成功；`400 VALIDATION`；`401`（缺密码/密码错，端点层）；`403 FORBIDDEN`（未授权客户端、host 被拒）；`429 RATE_LIMIT`；`404` 未知端点；`500 INTERNAL`。
- 载荷与 IPC 同构（`{ok,data}` / `{ok:false,error:{code,message}}`），工具入参多传或传未知字段一律 `VALIDATION`，不静默忽略。

### 1.3 限流与熔断
- 默认 60 req/min，突发 10；超限返回 `429 + {code:'RATE_LIMIT'}`。
- Runner 类长任务并发上限 3，超出排队；队列满返回 `BUSY`。

## 2. 内嵌 MCP Server

### 2.1 两种传输
| 传输 | 用途 | 配置 |
|---|---|---|
| stdio | 本地 AI 客户端把 ToAPI 当子进程拉起 | `{"command": "toapi", "args": ["mcp", "--db", "<toapi.db>"], "env": {"TOAPI_OPEN_SECRET": "<调用密码>"}}`；纯 Node 运行，不需要 Electron 运行时 |
| Streamable HTTP | 已运行实例被多个 AI 会话复用 | 与 §1 同端口的 `POST /mcp`，同 Bearer 鉴权；一次请求 = 一条 JSON-RPC（支持批量数组） |

stdio 模式即使 GUI 未开也能工作（`toapi mcp` 走 `createKernel({headless:true})`，与 `toapi run` 同一条无头路径）；GUI 运行时两者可并存。只实现 MCP 的 tools 面（`initialize / ping / tools/list / tools/call`），resources 与 prompts 不做 —— 能力都在工具里；通知（无 id）静默接收。

### 2.2 暴露的 MCP Tools（命名与语义稳定，进版本兼容承诺）
| Tool | 说明 | 类型 |
|---|---|---|
| `toapi_list_projects` | 项目/集合/接口树（含 id、名称、方法、URL） | 读 |
| `toapi_get_project` | 项目定义：根集合 auth、变量、前后置脚本、伪装 | 读 |
| `toapi_list_apis` | 项目内接口清单，可按集合过滤 | 读 |
| `toapi_get_api` | 接口完整定义（脚本/提取器/伪装/鉴权） | 读 |
| `toapi_list_envs` / `toapi_get_env` | 环境与变量；secret 值返回 `***` | 读 |
| `toapi_send_request` | 发送接口（apiId 或 draft + envId），返回 SendResult | 执行 |
| `toapi_run_collection` | 跑集合/项目/单接口 Runner，支持 `iterationData` 与迭代数，同步返回逐项结果 | 执行 |
| `toapi_get_run` / `toapi_list_runs` | 运行结果与历史运行 | 读 |
| `toapi_get_history` | 按项目/接口查最近请求响应 | 读 |
| `toapi_set_runtime_var` | 只写内存里的运行时变量（不落库、不写 secret） | 执行 |
| `toapi_export_tapi` | 导出 `.tapi` 内容，**恒定剔除 secret**（不提供 plain 选项） | 读 |
| `toapi_get_skill` | 生成项目 SKILL.md 正文 + 示例文件清单（§3） | 读 |

入参校验在 `electron/open/tools.ts`：未知字段、类型不符、超长字符串一律 `VALIDATION`，不接受隐式忽略；JSON Schema 由同一份字段表生成（`additionalProperties:false`），保证文档、Schema、校验器不漂移。

### 2.3 安全闸门（`electron/open/service.ts`，顺序固定）
1. **开关与密码**：`enabled=false` 或未设密码 → 直接拒；Bearer/环境变量密码校验（常量时间比较）不过 → 拒。
2. **限流**：默认 60 次/分钟滑动窗口，超出 `RATE_LIMIT`（HTTP 429）。
3. **客户端授权**：客户端 id 由名字哈希派生；首次连接在 GUI 弹授权条（含「将交付的说明书摘要」），60s 无操作按拒绝；已授权列表可在设置里逐个撤销。
4. **host 白名单**：发送/运行类工具的目标 host 必须落在项目环境声明的 host 清单内（由接口 URL × 各环境变量取值算出），否则逐次弹确认，确认后在同一会话内记住；**无 GUI 模式直接拒绝**（没人可问）。
5. **脱敏**：返回值按项目作用域收集 secret 明文做全串替换（响应体、脚本日志、错误信息都过），审计摘要同样脱敏且不含 `password`/`token` 字段值。
6. **审计**：每次调用（含失败）写 `external_call_log`，设置面板可回看；secret 变量任何通道不出明文。

**明确不暴露**：删除项目/接口/集合、清空历史、写 secret 变量、`secrets:'plain'` 的 `.tapi` 导出、导出保存对话框。

## 3. MD Skill 文件（无 MCP 的 AI 协作）

### 3.1 概念
Skill 文件 = 一份给 AI 看的 Markdown 技能说明书（`SKILL.md` 风格）：frontmatter 描述能力 + 正文给出"何时用、怎么调、参数是什么、示例代码"。AI 客户端（支持 skill 机制的）加载后即可直接调用目标 API——不经过 ToAPI 也能工作。

### 3.2 导出：三种交付方式
```
（1）toapi_get_skill 工具 / GET /v1/skill —— 直接返回 SKILL.md 正文与示例清单，AI 拿到即用
（2）首次授权时随授权条展示说明书摘要，用户知道会交出什么
（3）集合/项目右键「导出 AI Skill 包」落盘为目录（尚未接 UI，生成器同一份：electron/open/skill.ts）
订单中心.skill/
├─ SKILL.md          # 技能说明书（见 §3.3）
├─ 订单中心.tapi      # 可选：同内容 TAPI，供有 ToAPI 的一方导入（恒定剔除 secret）
└─ examples/
   ├─ login.py / login.js / login.sh   # 关键接口的可跑示例
```

### 3.3 SKILL.md 生成模板
```markdown
---
name: order-center-api
description: 订单中心 staging 环境接口调用技能。当需要创建订单、查询订单、
  取消订单或做订单链路回归时使用。baseUrl 见"环境"一节，鉴权走登录接口取 token。
---

# 订单中心 API 技能

## 环境
- baseUrl: https://staging.example.com（如对方给了其他环境，替换即可）
- 变量: {{username}} {{password}} 需向接口提供方索取

## 调用顺序（链式约束）
1. 先调「登录」取 token（见示例 examples/login.py）
2. 后续请求带 Header: Authorization: Bearer <token>

## 接口清单
### 登录 — POST {{baseUrl}}/api/login
请求体: {"username": "...", "password": "..."}
响应: 200 时 data.token 为令牌，有效期 2h
断言建议: status == 200 且 data.token 非空

### 创建订单 — POST {{baseUrl}}/api/orders
...（每个接口一节：方法、URL、头、体、提取器语义、已知坑）

## 验证方式
调完后可用「查询订单」回读确认；或把本目录 订单中心.tapi 导入 ToAPI 一键回归。
```

生成规则：
- 从集合数据自动组装：接口定义、提取器链（推导"调用顺序"节）、断言转为"断言建议"、伪装配置转为注意事项。
- secret 变量只列名字，永不出值；frontmatter `description` 写清"何时用"，这是 AI 选择该技能的唯一依据。
- 生成后可人工编辑，App 不覆盖手改（同 testgen 三路合并原则）。

### 3.4 导入/识别
打开外部收到的 SKILL.md：解析 frontmatter + 接口小节 → 生成项目草稿（复用 10 号文档 MD 解读管道，置信度标记相同）。

## 4. 能力矩阵（三条通道对比）

| 能力 | GUI | Local API | MCP | MD Skill |
|---|---|---|---|---|
| 发送请求 | 有 | 有 | 有 | AI 自行构造 |
| Runner（含数据驱动迭代） | 有 | 有 | 有 | 无（只给断言建议） |
| 读项目/环境/接口定义 | 有 | 有 | 有（脱敏） | 有（文档化） |
| 运行时变量（会话内） | 有 | 有 | 有 | 无 |
| 写环境 secret | 有 | 无 | 无 | 无 |
| 删除/清空 | 有 | 无 | 无 | 无 |
| 导出 TAPI | 有（可选明文） | 有（**恒定剔除 secret**） | 有（同左） | 包内附带 |
| 取 SKILL.md | 有（写盘待接） | 有 | 有 | 本体 |

## 5. 数据结构（已落迁移，见 03 号文档 §4）

- `app_settings(key TEXT PK, value TEXT)`：key `open.config` 存 `{enabled, port, access, ratePerMin, salt, hash, passwordSetAt, clients[]}` —— **只存 scrypt 派生值，永不存明文密码**。
- `external_call_log(id, channel:'http'|'mcp', tool, client, params_summary, ok, error_code, time_ms, created_at)`，`(created_at DESC)` 索引，插入后环形裁剪到最近 5000 条。
- 局域网节点协议 `toapi-node/1` **复用同一份 `open.config`**（24 号文档 §2）：`salt` 作为 KDF 上下文经 `/v1/node/hello` 明文下发（不是秘密），`hash`（口令的 scrypt 派生值）就是信道预共享密钥，因此服务端不需要知道口令明文；节点自己的密钥与审计落在 `node` / `node_call_log`（03 号文档 §3.7i），不写 `external_call_log`。

## 6. IPC / 测试

- IPC：`open:get-config` / `open:set-config`（含密码、端口、限流、访问范围）/ `open:rotate-token` / `open:list-clients` / `open:revoke-client` / `open:call-log` / `open:approval-result`，事件 `event:open-approval`（04 号文档 §3.5）。
- 测试（已并入 07 号文档 §2.8）：
  - 未设密码时无法启用、弱口令被拒、清除密码即关通道；错误密码 401 且写审计
  - 限流触发 429 + `RATE_LIMIT`，恢复后立即放行
  - host 白名单外的 draft 请求在无界面模式直接 403；白名单内正常
  - MCP：`initialize → tools/list → tools/call` 全链；错密码 `isError`；未知工具/非法入参是工具级错误不是协议崩溃；通知不回包
  - secret 在任何通道不出明文：环境变量、`.tapi` 导出、HTTP 响应（含靶场回显的请求头）、审计摘要
  - SKILL.md：frontmatter 合规、只列敏感变量名、附示例文件清单

## 7. GUI 面（06 号文档 §3.9 / §5）

- 命令面板「开放调用设置（HTTP API / MCP）」打开设置面板：启用开关（未设密码时禁用）、监听地址分段（仅本机 / 局域网，后者需勾二次确认）、端口、调用密码（自定义 / 生成一次性的，只显示一次并要点「已记录」）、已授权客户端列表与撤销、外部调用记录、接入方式代码片段。
- 勾选「局域网」后面板出现一条提示（`data-testid="open-lan-hint"`）：明文 `/v1/*` 端点跨机不加密，只建议本机脚本使用，跨机互传与代为测试必须走「节点」面板的加密配对（24 号文档 §2.2）。
- 授权条：底部居中浮层（Toast 之上），显示客户端名 + 事由 + 可展开的说明书摘要，「拒绝 / 允许」两枚药丸；60s 无操作按拒绝处理并自动消失。

## 8. 与 AI 助手（内置）的边界

内置 AI 助手（16 号文档）走 Provider 出网，与本文的"被 AI 调用"是反方向能力，互不共享开关：助手不能读 `open.config`，也不因助手开启而暴露本地端口。
