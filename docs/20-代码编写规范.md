# ToAPI — 代码编写规范

> 目标：任何人（或 AI）写的代码看起来像同一个人写的。
> 未在本规范明示的场景，以"与相邻代码保持一致"为准。

## 1. 语言与工程基线

- TypeScript `strict: true`，`noUncheckedIndexedAccess: true`；`any` 禁止（确需时用 `unknown` + 收窄）。
- Node 目标版本 = Electron 内置版本，写进 `.nvmrc` 与 `engines`。
- ESM only；禁止 `require`（Python 桥接等原生边界除外）。唯一例外是 `bin/toapi.cjs`：npm `bin` 入口必须能在纯 Node 下加载 esbuild 的 CJS 产物，因此写成 CommonJS 引导壳，只 `require` 一个文件、不含业务逻辑。
- 路径别名：`@shared/*`、`@main/*`、`@renderer/*`，禁止跨层相对路径（`../../..` 两级以上即违规）。

## 2. 命名

| 对象 | 规则 | 例 |
|---|---|---|
| 文件 | kebab-case | `cookie-jar.ts` |
| 类/类型 | PascalCase | `RequestFlow`、`SendResult` |
| 函数/变量 | camelCase，动词开头 | `resolveVars` |
| 常量 | SCREAMING_SNAKE | `MAX_REDIRECTS` |
| channel | `域:动作` 全小写 | `runner:start` |
| DB 表/列 | snake_case | `runner_item.sort_order` |
| 布尔 | is/has/can/should 前缀 | `isActive` |
| 事件处理 | handleXxx / onXxx | `handleSend` |

## 3. 函数与模块

- 函数 ≤ 40 行、参数 ≤ 4 个（超出用 options 对象）；嵌套 ≤ 3 层（早返回替代嵌套）。
- 模块单出口：目录下 `index.ts` 只 re-export，不写逻辑。
- 纯函数优先：`codegen`、`vars`、`cron` 解析等必须是无副作用纯函数（可单测、可快照）。
- 副作用集中：文件/网络/DB/时间只经基础设施层；领域服务通过构造函数注入拿依赖（便于测试替换）。

## 4. 错误处理

- 跨层传递用 `Result<T>`（17 号文档 §5），不用异常当控制流；异常只表示"程序员错误"。
- 系统边界（IPC 入口、子进程、外部 HTTP、文件 IO）必须捕获并翻译为 `IpcError`/`Result.err`。
- 禁止空 catch；catch 至少记日志（含上下文 id，如 runId）。
- 错误文案面向用户写中文，面向日志写英文 + code。

## 5. 日志

- 统一 `infra/logger`：`log.info('[runner] started', { runId })`，模块名方括号前缀。
- 级别：debug（默认不写文件）/ info / warn / error。
- **脱敏中间件强制**：命中 secret 变量值、Authorization 值、api_key 模式的一律替换 `***`。
- 响应 body、完整 prompt 不进日志（只进摘要与长度）。

## 6. 注释

- **每个源码文件第一行是作者声明**：`// @author yxpil`（CSS 用 `/* @author yxpil */`，YAML 用 `# @author yxpil`）；带 shebang 的脚本把 shebang 保持在第 1 行、声明紧随其后。新增文件必须带上，缺失由 lint/评审拦下。
- 除作者声明外默认不写注释；只写"为什么"（隐藏约束、变通原因、外部怪异行为），一行以内。
- 禁止注释掉的死代码、禁止 `// TODO` 无 tracking（要么建任务要么删）。
- 公开契约（`shared/` 类型、channel 语义）以 04/18 号文档为准，代码里不重复文档。

## 7. UI 代码

- 组件 ≤ 200 行；样式只用 `tokens.css` 变量（禁行内色值/字号魔法数）。
- 图标只经 `<Icon name="check" />`（内联 SVG 注册表），禁 emoji、禁外链图标库。
- 交互控件必须有：hover/focus/disabled/loading 四态；按钮必须有 `title` 快捷键提示。
- 列表超 100 条必须虚拟滚动；异步操作必须有 pending 态与取消路径。
- a11y：可点元素可 Tab 到达；功能性图标配 `aria-label`。

## 8. 安全红线（提交前自查）

- 渲染进程无 Node API；preload 只暴露白名单。
- SQL 全部参数化（better-sqlite3 prepared statement），禁字符串拼接 SQL。
- 用户脚本/AI 输出不直接 `eval`；只进沙箱/草稿流。
- secret 值不出现在：日志、通知、Webhook、TAPI 默认导出、AI prompt、审计摘要。
- 新增依赖需 PR 说明（体积、维护度、License），原生依赖需说明 prebuild 矩阵影响（14 号文档）。

## 9. Git 与 PR

- 提交信息：`type(scope): 中文摘要`，type ∈ feat/fix/refactor/test/docs/chore；scope = 模块名（如 `runner`、`ipc`）。
- 分支：`feat/<scope>-<短述>`；PR 模板含「契约变更」勾选框（改了 shared/ 或 04 号文档必须勾选并附文档链接）。
- PR 门禁：lint + typecheck + 单测 + `check-channels` 全绿；契约变更需额外过集成测试。
- Commit 不夹带无关格式化；格式化单独 chore 提交。

## 10. 文档同步义务

改以下文件必须同步改文档（PR 模板有对应 checkbox）：
| 代码变更 | 同步文档 |
|---|---|
| `shared/channels.ts` | 04 号文档 channel 表 |
| DB migration | 03 号文档表结构 |
| 沙箱 `toapi.*` / `pm.*` API | 05 号文档 §2、23 号文档 §4 |
| UI tokens/组件行为 | 06 号文档 |
| 任何流程时序 | 17 号文档 §3 |
